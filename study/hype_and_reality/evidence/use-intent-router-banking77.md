# Fine-tuned encoder intent router vs structured-output Claude, with measured out-of-scope rejection

- **Sources:** https://github.com/smallestbusiness/intent-router README (repo created 2026-09-17; owner smallestbusiness) (accessed 2026-10-02; locators: "Results", "Escalation threshold", "Against an LLM doing the same job", "Does a negative class help?", "Re-calibration: compare at matched cost", "Is a dedicated model needed to separate insurance from banking?")
- **Evidence type:** user anecdote / author evaluation with reproducible scripts (single-author hobby-scale project, synthetic banking copilot); author independence: independent of Jev
- **Model / base / checkpoint:** distilbert-base-uncased, xlm-roberta-base, xlm-roberta-large + LoRA (560M, 0.48% trainable); LLM baseline claude-sonnet-4-6 with 77-value enum tool and forced tool choice; **size:** stated in README; **training:** BANKING77 train (13,083 queries, 77 intents)
- **Task:** 77-way banking intent routing, plus off-topic rejection; **input language:** English, Hebrew slice (machine translated); **options / readout:** max softmax; **rejection mechanism:** (A) confidence threshold, (B) added 78th out_of_scope class, plus escalation to LLM
- **Data provenance:** in-domain = real BANKING77 test (3,080); OOS negatives are LLM-generated by the author (train 200 in 5 categories; test seen 72; test unseen 120 across travel, medical, techsupport, insurance, tax, injection); **n:** as stated; **metrics:** accuracy, false rejection of real customers, OOS recall; **raw cases available:** scripts in repo (not inspected)
- **Fixed / mitigated?** yes, cascade; **fix evaluated?** yes

## What the source reports
- In-domain: xlm-r-large+LoRA 94.2% vs Claude Sonnet 4.6 85.3% (150 requests per language, uncached), at 12 ms vs ~2 s p50: the author attributes this to 10k labelled examples of a very narrow task.
- Threshold only (t=0.75) on 77-class model: 6.59% of real customers falsely rejected, unseen-OOS recall 86.7%; weakest category insurance 75% (adjacent domain).
- Adding a negative class trained on 5 unrelated categories caught 100% of seen categories but only 21.7% of unseen via the class itself; the author's first reading ("it hurts the threshold") was retracted after comparing at matched false-rejection budgets (e.g. at <=3% false rejection: 63.6% vs 70.8% vs 85.6% with adjacent negatives).
- Training insurance+tax as negatives raised insurance 75% to 95% with no in-domain cost, but held-out neighbours (pension 76 to 84%, crypto, broker unchanged) did not transfer: it learned those categories, not "not ours".
- Class-only recall on unseen categories rose from 21.7% to 69.7% when negatives spanned two kinds rather than one (variety matters more than count).
- Prompt-injection OOS category reached 95-100%, which the author flags as not adversarial (20 generated examples).

## Strength and caveats
- Supports: (1) small fine-tuned encoders can beat a frontier LLM on closed-set routing when trained on in-task data; (2) rejection works with a closed set only if threshold or negative class is calibrated against a false-rejection budget; (3) the product tolerates errors through an LLM escalation fallback; (4) adjacent-domain negatives are the hard case (compare L3).
- Single author, no peer review, LLM-written negatives, English-only negatives, no real traffic.
- Relevant local classes: L2, L3, L8; Q1, Q3, Q5, Q7.
