# Trained Jev-style encoders and small decision heads: size evidence and out-of-domain gaps (Verdict, open-jev-deberta, Laya, Von, GLiNER2.5-Decide)

- **Sources:** HF cards/APIs: https://huggingface.co/heman10x/rlcd-modernbert-151m ; https://huggingface.co/com-kotobalabs/open-jev-deberta-v3-large ; https://huggingface.co/convaiinnovations/laya ; https://huggingface.co/wfzyx/von ; https://huggingface.co/fastino/GLiNER2.5-Decide and `-1B`; GitHub READMEs: https://github.com/Heman10x-NGU/openJev-verdict-2.0 , https://github.com/NandhaKishorM/laya , https://github.com/wfzyx/von (accessed 2026-10-02). The Verdict E9 figure (README table E9), the Laya base-checkpoint figures (README typed-decisions table) and the GLiNER2.5-Decide benchmark table (card) were re-read at the primary source; the other numbers (Verdict Banking77, DeBERTa, Von JevBench) come from `study/open/` notes and are unverified here.
- **Evidence type:** author/vendor evaluation; one JevBench cross-reference is independent (see `scale-jevbench-cross-model-and-jeff-hard-tier`). Author independence: no.
- **Model / checkpoint (HF API verified 2026-10-02):** `heman10x/rlcd-modernbert-151m` 151,378,176 params, base knowledgator/gliclass-modern-base-v2.0, Apache-2.0 metadata (GitHub licence NOASSERTION); `com-kotobalabs/open-jev-deberta-v3-large` 434,012,160 params, base microsoft/deberta-v3-large, Apache-2.0; `convaiinnovations/laya` 421,293,830 params (F16), `laya-multilingual` 321,908,998, Apache-2.0, download counter 0; `wfzyx/von` 394,781,696 params F32, base answerdotai/ModernBERT-large, Apache-2.0; `fastino/GLiNER2.5-Decide` 486,444,053 params (card says 340M), base fastino/gliner2-large-v1; `GLiNER2.5-Decide-1B` 1,188,796,693 params, base fastino/gliner2-xl-0111; `heman10x/openJev-verdict-2.0` HF API not retrievable (error), GitHub repo exists.
- **Task / readout:** marker-token or GLiClass-style label heads, one encoder pass; Von and Laya are `/v1/systemone`-compatible servers; Verdict has a Python SDK and possibly no HTTP server (not found in README).
- **Rejection mechanism:** Verdict v1 has an explicit `__insufficient_evidence__` slot; others none.
- **Relevant local classes:** L2, L3, L4, Q1, Q3

## What the source reports
- Verdict v1 (151M, GLiClass-derived): in-domain Banking77 95.0% with 5 candidates falling to 72% at 25; abstention recall 97.5% on OOS but 10% on hard negatives/synonyms; on TypeSafe's public cases (337) 48.07% vs Jev 90.80% (author's own E9 audit). Abstention learned on in-distribution OOS did not generalise.
- open-jev-deberta-v3-large (434M, trained on 18k states from Banking77/SST-5/BoolQ): in-domain 0.854, out-of-domain 0.690, unseen ordered scales near majority (0.45 vs 0.26); JevBench hard-tier 37.8%.
- Laya (421M ModernBERT-large): shipped zero-shot checkpoints near chance on typed-decisions (`laya` 0.362, `laya-multilingual` 0.352 vs majority class 0.461; README, typed-decisions table and 'base checkpoints sit below the majority-class baseline'); the fine-tuned `laya-typed-decisions` 0.766 in-distribution. The `noul` option-label-over-state problem (issue #156) is from the study note; unverified here.
- Von (395M): order-invariant attention; JevBench v1.4 sealed 0.279 (ECE 0.107) vs jeff 0.331 and Laya 0.308 per the Von card; Jev 0.367. English only, calibration map fitted on public JevBench items (in-sample).
- Size comparison inside the encoder class: 151M (Verdict) vs 395-434M (Von, Laya, DeBERTa, jeff) shows no consistent ordering; GLiNER2.5-Decide 340M(486M) 60.2% vs the 1B version 59.6% on the vendor's own fast-decisions benchmark (card table, vendor's own fast-decisions benchmark, which also lists GLiFormer large-v1 at 49.0% and Laya Router at 46.6%), i.e. a 2.4x larger encoder did not help there. Training data, not parameter count, appears to dominate in this class.
- Apple Silicon: Von documents `--device mps` (auto cuda/mps/openvino/cpu); Laya CLI accepts `--device mps`, with third-party MLX (laya-mlx, 6.7k stars, Apache-2.0, M3 Max FP16 13.42 ms P50 author-measured) and Core ML ports; DeBERTa-v3 model card says CPU is slow (M1 Max CPU fp32 1.8 s for 4 questions).

## Strength and caveats
- Shows that encoders trained on a few public sets (or fine-tuned on in-distribution OOS) do not carry abstention or reasoning to new distributions, consistent with L2/L3 persisting even for trained class-B models. Size alone is not the lever in this class; no encoder family offers a medium and large size with identical training except GLiFormer (generic only).
- Several figures come through secondary notes (flagged above); treat as leads.
