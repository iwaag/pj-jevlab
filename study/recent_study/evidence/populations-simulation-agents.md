# Populations, simulations, games and agent control loops built from decision models

Theme summary. Eight recent arXiv papers (23 Sep - 7 Oct 2026) use Jev-style typed decision models (or, for one adjacent paper, a generative LLM) as the decision layer of populations, simulations, games and agent loops. The consistent message is a division of labour: code builds the view, owns the simulation, the random numbers and the aggregation, and the decision model only evaluates a listed set of options. Where results are aggregated (election shares, effect sizes, school behaviour) per-decision error is tolerated, but systematic, shared error (partisan lean, shared discrepancy, one lure option) does not average out with N; where a single trajectory must be right at every step (tau-bench, Doom, StarCraft) per-decision error compounds. Nobody else in this batch measures the effective number of independent votes in a population of one model, which is the lab's set6 p1 claim.

Conventions: lab codes J, G, K27, W12, A27, D35, L27 and the experiment names (game_test, set1-set6, "item 1/6/7") follow the lab summary written for this survey from the episode reports under `devdocs/episodes/`. All papers accessed 2026-10-08 from local pdftotext output. Figures marked "(skimmed)" were not read line by line.

## 2609.27535 — KITE: Scaling Jev Population Experiments with Sparse Flagship Calibration
- Hengyu Li (Univ. of Tokyo), submitted 23 Sep 2026, https://arxiv.org/abs/2609.27535; read: full text (PDF via pdftotext), accessed 2026-10-08 (appendices skimmed).
- Systems and readouts tested: Jev 1.13.0 as a "kernel" (one Noul probability per answer option, bundled in one request, renormalised, third-person "what would the described respondent answer"); GPT-6 Astra as sparse "flagship" anchor; GPT-5.6 Luna as cheap comparison tier. Code does all arithmetic, sampling and weighting.
- Design: Epstein misinformation experiment (9,070 participants, 5 waves, 8 interventions, 20 cards); SocSci210 (210 TESS experiments, 37 held-out intervention comparisons); Arechar (16 countries, 45 headlines). Pre-committed ("frozen") criteria, bootstrap over participants/studies. Compared kernel only, hybrid (kernel + paired flagship anchors), direct flagship audit, human half-sample pilot. Persona states rendered from microdata covariates; identical rendered states share one cache entry.
- Key results (numbers as reported):
  - Execution: kernel queried once per unique state, then any number of agents are run from the table with inverse-CDF sampling, using an event-keyed uniform variate (seed, agent, step, event), so treatment arms use common random numbers (CRN). 29.2% of "fresh" states in the scale workload were exact repeats (S1). 10^6 agents x 20 steps in 0.90 s on a laptop (Table 3); scalar engine 10^4 agents 0.95 s. CRN cut effect SD from 0.00303 to 0.00072 (about 18x variance) over 100 seeds. A weighted-expectation (Rao-Blackwell) estimate removes draw noise entirely (eq. 1).
  - Cost: Jev $0.0227 per 1,000 fresh predictions, median latency 213 ms; Astra roughly 300-450x costlier per prediction (Sec. 9).
  - Sparse anchors: Epstein effect MAE 0.0305 -> 0.0180 (-41%; paired gain 0.0125, 95% CI [0.0064, 0.0167]) with 1,080 anchors (1.7% of 64,000 states), flat in persona count from 10 to 200 per wave (Table 2, Fig. 2B). SocSci210 captured decision gain 0.268 -> 0.386 with 3 paired anchors per condition (1.5% coverage), gain +0.119 [0.014, 0.224]; one anchor already +0.114 (Sec. 7.2). Not shown: Epstein preregistered policy-value gain (+0.0027 [-0.012, 0.017]); headline heterogeneity (within-arm r 0.157); pairing beating equal-budget unpaired anchors; raw effect MAE on SocSci210 got worse (0.052 -> 0.083), magnitude ratio 1.75 vs 0.68.
  - Discrepancy propagation: fit theta = beta*x + b_s + u_sa, with study-level b_s ~ N(0, tau^2), tau = 0.037 [0.021, 0.046], sigma = 0.080 [0.051, 0.128] (Eq. 4, Sec. 8). The shared discrepancy scale sqrt(tau^2+sigma^2)=0.088 exceeds persona-sampling SD (0.0235 at 5 respondents/cell, 0.0033 at 100; Fig. 3A). Retrospective coverage on 37 unseen studies 0.93/0.96 at nominal 0.80/0.90, versus 0.29/0.36 with human-sampling uncertainty only. Intervals are conservative (selected reliable studies), slope unstable (beta 0.925 on seen set, about 0.5 on test reliable contrasts), and transport to Epstein is uninformative (half-width 0.145 > largest effect 0.062).
  - Saturation: sign accuracy 0.632-0.674 and gain 0.255-0.358 show no rising trend from 5 to 200 simulated respondents per cell (Sec. 5). A demographic-group predictor has individual-response correlation 0.013.
  - Correlated error across tiers: Jev, Luna and Astra err together on 19.4% [9.6, 32.9] of reliable contrasts vs 3.5% expected under independence (Sec. 9).
  - Kernel intervention-sensitivity gates failed on Arechar (prompt effect -0.034/-0.060/-0.102, wrong sign); content/ranking gates passed 15/15 new countries.
- Proposed method or recipe, and its cost: the K-I-T-E pipeline (kernel, intervention anchors, tabulated execution, error propagation); exponential "tilt" of each kernel distribution so the cell mean matches the flagship's paired effect (eq. 3; requires >= 6 paired anchors per cell, probability floor 0.005); shared discrepancy draw once per study and arm; per-property evidence records. Cost: about $1.60 kernel + about $90 Astra for Epstein D1 (4.1M tokens); about $22 for the SocSci210 anchors.
- Authors' stated limitations: only two independent human-referenced tests; sparse calibration can import flagship errors (Epstein wave 5); magnitudes need further calibration; cannot license literature-absent interventions (recall vs inference unresolved, A3c); tabulated execution cycles 500 personas through the table and is fixed-exposure, no network dynamics; memory tier is a rank-preserving offline mapping not an online process; proprietary model, cache not released. My caveats: single author, single vendor model; "human" truth is survey data on misinformation headlines, so none of the validity claims transfer to the lab's rule-referenced game setting; the 41% gain rests on 10 effects.
- Relevance to the lab: item 7 (set6 p2 fish school) primarily, item 6 (set6 p1) secondarily. Verdict: **extends the lab's finding** (and is partly a parallel of the view cache).
  - What KITE adds beyond the lab's view cache (query once per unique view): (1) Randomness is injected after the model, per agent and per event, from an event-keyed uniform variate used to invert the model's CDF; so unpredictability is a controlled, reproducible sampler, not repeated model calls (which would add nothing; see 2609.36399 ICC 0.997), and counterfactual arms see identical randomness (CRN). (2) Draw noise can be removed analytically by computing the expectation over the table, so a 300-agent statistic can be reported with no sampling noise at all and only the shared term left. (3) Human-model discrepancy is a single draw per study and arm, shared by every agent, so it never shrinks with N; the lab's finding that "random view-fixed errors or per-agent side bias are much worse than the 21% structured errors" is the same issue seen from the other side: error that is a fixed function of the view is shared by all agents seeing that view, so its effect depends on its structure (hold-course on one redundant branch is harmless; side bias is not). KITE gives the language (shared vs independent error) and an estimator for it; the lab gives the empirical case where the shared error is benign. (4) Sparse anchors: with a rule as oracle, the lab can evaluate the rule on every view for free, so full "calibration" is cheap; KITE's cell-wise tilt is a candidate repair for biased mean behaviour (e.g. a side bias) but would not fix the lab's hold-course errors, which are not a mean shift.
  - Persona count curve is flat (10-200 per wave), the same message as set6 p1 (n* = 1.0): more persona-varied copies of one model buy nothing; KITE also finds that all three model tiers share 19.4% errors, matching the lab's finding that only different models behave like several deciders.
  - Reusable idea: report every school/village statistic as (conditional expectation over the view table) plus (run-level shared discrepancy draw) rather than as a Monte Carlo mean over 300 agents; test whether the lab's 21% "structured" error needs a tau term to match the rule school's variance across runs.

## 2610.03935 — General Decision Models: Benchmarking and Insights Beyond Jev (JEVal; InnerJev)
- Feiyu Duan, Jiayu Lin, Jia Wang, Jun Xiang et al. (Shanghai Innovation Inst., Fudan, others; corresponding author Zhongyu Wei), submitted 2 Oct 2026, https://arxiv.org/abs/2610.03935; read: full text (PDF via pdftotext), accessed 2026-10-08. Read closely: intro, Sec. 5.1, 5.3, 5.4, 6, 7-9, App. E.3; skimmed: benchmark construction, per-domain tables.
- Systems and readouts tested: Jev 1.13 (hosted); 25 configurations of decision models (Kev-0.8B...27B, OpenJev, Intern-Decision-4B, Laya, NanoJev...) and generative LLMs with/without thinking; new InnerJev-4B/27B (open, from Qwen3.5-4B and Qwen3.8-27B) read from the first-token logits restricted to option labels (a letter-logit readout, like W12/A27 in the lab).
- Design: JEVal = 11,257 bilingual instances, 36 datasets, 10 domains. Probability probes (Sec. 5.1); tau-bench Retail/Airline with Jev choosing the next action (tool or respond) and the same DeepSeek-V4-Flash filling arguments (Sec. 5.3, one run per task); social simulation at 3 levels: user-interest profiling (898 accounts), SocioBench individual survey prediction (277,500 respondent-question pairs, 10 domains), and ElectionSim 2024 US presidential election with InnerJev-27B driving about 330,000 voters (1/1,000 sample), each voter asked under both option orders, state share = voter-weighted mean of P(Harris) (Sec. 5.4.3).
- Key results:
  - Probability compression (Sec. 5.1): Jev picks the mode on 100/100 prior items but gives the true mode 89.35% mean mass vs 35.60% in the true distribution; on posterior items its top-2 options hold 90.30% of mass. Authors: "any downstream use that averages or thresholds probabilities inherits the distortion."
  - tau-bench (Table 3, Sec. 5.3): Pass 77.6% (base) -> 66.1% (Jev + LLM) overall (Retail 86.1 -> 73.9; Airline 58.0 -> 48.0), P50 time 267 s -> 161 s, P95 696 s -> 816 s, mean turns unchanged (13.4). Errors in action choice or in arguments cause retries and recoveries; slow tail concentrates among failures. (Internal inconsistency: the text of Sec. 5.3 quotes 64.2% pass, P50 156 s and P95 1,010 s, which differ from Table 3.)
  - Profiling (Table 4): Jev mean Jaccard 53.88% with the reference profiler vs 65.24% (Qwen3.8-27B non-thinking); exact set match 15.03% vs 25.06%.
  - Individual survey prediction (Table 5): Jev 37.69% accuracy at 0.50 s per item; InnerJev-27B 39.87% (8.4 s on their serving); best LLM (thinking DeepSeek-V4-Flash) 40.41% at 212 s; thinking adds only 2.5-3.2 points.
  - ElectionSim (Table 40, Fig. 8): InnerJev-27B calls 47/51 states, 12/15 battlegrounds vs 46/51 and 11/15 for the original GPT-4o-mini pipeline; but vote-share MAE 6.52 pp vs 3.06, RMSE 9.42 vs 3.80, bias +3.73 vs +2.31 pp. All four misses are Trump states called for Harris; biggest errors in sparsely sampled states (Wyoming, Alaska). All runs, including two Jev runs (one at 1/100,000 sampling, one demographics-only with thousands of voters per state), overestimate the Democratic share by 2-6 pp; in the demographics-only run liberal Republicans defect about twice as often as conservative Democrats. Cost: two forward passes per voter, no generated tokens.
  - InnerJev: Reasoning-to-Readout Self-Distillation (two thinking chains per question, average their end-of-reasoning option distributions, train the no-reasoning first-token readout to match; KL anchor to the frozen readout; 39,279 questions, no gold labels) gives InnerJev-27B about 2 points above Jev on JEVal accuracy, lowest ECE, about 110 ms on one H100; gain is on label-selection tasks, a quarter or less of the thinking gain on GPQA/MMLU-Pro (Sec. 6.3).
- Proposed method or recipe, and its cost: JEVal as a benchmark; InnerJev recipe (single epoch, full-rank or LoRA, no new head). Cost is about 2 x chain generation for 39k questions plus one epoch; not given in dollars.
- Authors' stated limitations: only two agentic settings; Jev is the representative model; the distillation is "an initial attempt".
  My caveats: the election run uses a single sample ratio and one pass, no seeds or confidence intervals; "calls the states" is a threshold-at-50% statistic, so a lean of a few points still leaves most states correct; no measurement of the spread of per-voter P(Harris) or of independence among voters; the original pipeline comparison is an archived output, not a matched rerun.
- Relevance to the lab: items 6, 7 (and 2 for the probability-compression point). Verdict: **extends the lab's finding** for the population question; **background** for tau-bench; **new idea** for the distillation recipe.
  - Social simulation vs set6 p1 ("aggregate estimation errors and systematic bias" vs about 1 effective vote). Persona-like variation here comes from different *inputs* (state, five demographics, recent posts) and the quantity of interest is a share, not a single right answer; the paper never asks whether voters are statistically independent, only averages P(Harris). Their result that errors are systematic (every run leans Democratic by 2-6 pp, errors do not shrink with thousands of voters per state) is exactly what set6 p1 predicts when agents from one model share an error pattern: aggregation removes noise but not bias, and the number of effective votes is about 1 for any question where the persona is not decisive. So a typed model's persona variation does produce spread in P (it must, to give state-level shares), but the paper provides no evidence that the spread is calibrated or independent; individual-level accuracy of about 38-40% on SocioBench says demographic persona carries little individual information. The two are compatible: the lab's n* = 1.0 is for questions with a correct answer driven by the evidence; JEVal's population is for opinion-like questions where the persona can legitimately move P.
  - Probability compression: Jev's overconfidence (89% on the mode vs 35% true) parallels the lab's set3 finding that models decide at p >= 0.8 when a decisive fact is missing, and it means that sampling an action from P (KITE style) gives much less variation than the truth; any "10-20% error as useful unpredictability" design needs temperature scaling or a calibration step first.
  - tau-bench: a conjunctive task (about 13 turns, success needs all steps) turns a per-step shortfall into a 11-point success drop; a school or village statistic is an aggregate, not a conjunction, which is why the lab's 21% per-agent error can leave the collective unchanged. The two are the two regimes any simulation design should state.
  - InnerJev-27B is built on the same Qwen3.8-27B as K27 and uses an option-letter logit readout (like W12/A27), so it is a candidate additional system for the lab's panel (different training signal, self-distilled from thinking mode, not a Jev-style fine-tune).

## 2609.36399 — Calibrated to Whom? Persona and Language Effects on Cultural Values in JEV
- Bushra Asseri, Abdulaziz Asseri (Alfaisal Univ.; Proxa.sa), submitted v1 Sep 2026 (v2 dated 3 Oct 2026), https://arxiv.org/abs/2609.36399; read: full text (PDF via pdftotext), accessed 2026-10-08 (appendix tables skimmed).
- Systems and readouts tested: Jev 1.13.0 only, Choice (and Score) questions returning a probability per option plus a confidence; expected answer scored on Hofstede VSM 2013 (24 items, five-point scales).
- Design: 12 matched Saudi and 12 matched American personas plus no persona, English and Arabic, 8 request designs (documented, LLM-style prompt, no format sentence, Score question, Score with reversed levels, third person, 24 items per call, other-language framing); 1,200 prompts x 30 calls per design = 288,000 answers. Reference = Saudi-minus-US difference in Hofstede's published scores (length 94.3); every measure compares two of the model's own profiles, so the VSM constants cancel. Bootstrap over matched profiles; exploratory, not preregistered.
- Key results:
  - Repeatability (Sec. 4.1, Table 4): ICC of the expected answer over 30 identical calls 0.995-0.998 (0.997 documented), SD across calls 0.026-0.032 on the 1-5 scale, but the most probable option is the same in all 30 calls for only 83-89% of prompts (so 11-17% of prompts flip their top option between identical calls; mean confidence 0.49-0.58, normalised entropy 0.49-0.69). The model has no temperature or seed parameter.
  - Persona sensitivity: changing the persona from American to Saudi moved the answers 87% (English) and 62% (Arabic) of the Hofstede difference along its direction (CI 80.5-93.9, cosine 0.82), yet the whole difference departs from Hofstede by about 60% of its size (long-term orientation reversed, indulgence gap nearly 3x the reference). Four of five differing dimensions in the right direction. No-persona default sits at 0.08 (English) / 0.06 (Arabic) on the American (0) to Saudi (1) axis.
  - Persona detail dilutes the national signal: country only 96% -> country + gender and age 85% (English); Arabic 81% -> 57% (Fig. 4b). Age shifted profiles about as much as nationality; gender stereotyped, larger for Saudi personas. The Arabic effect is associated mainly with the language of the items (-29.5 points) not of the persona text (-3.9).
  - Confidence is lower in Arabic by 0.090 (all 25 personas); but confidence measures model certainty, not agreement among people.
- Proposed method or recipe, and its cost: an audit protocol (constant-free comparisons, language cross, eight request designs). Cost in an appendix (not read).
- Authors' stated limitations: one model version; one official Arabic translation; Hofstede scores are from unmatched samples and periods, not ground truth; 12 constructed personas and 24 items only; exploratory.
  My caveats: "highly repeatable" ICC is over repeated identical calls of the same prompt, i.e. it says the API is nearly deterministic, not that responses to different personas are stable; it does not measure between-persona spread against within-persona noise.
- Relevance to the lab: item 6 (persona populations). Verdict: **extends the lab's finding** (explains why persona-only populations carry little independent information) with one qualification; **new idea** on near-tie flicker.
  - ICC 0.997 means repeated asking adds nothing: all variation in a Jev-style population must come from the *input* (persona text, view) or from an externally injected sampler (as in KITE). That matches the lab's set5 result (re-asking a one-pass scorer has nothing to work with) and set6 p1 (24 personas = 1.0 effective vote). Persona text does move the answer in the expected direction on a value question with no correct answer (87% of the benchmark direction in English), so persona populations are not degenerate for preference questions; but the movement is stereotyped (age and gender), is diluted by each added attribute, and is still a deterministic function of the persona string, so a 300-villager population built from persona strings has exactly as many distinct behaviours as it has distinct strings.
  - Reconciliation with set6 p1: on questions with a decisive piece of evidence, persona is a weak signal compared to the evidence, so persona agents make the same errors (mutual agreement 0.90-1.00). On opinion questions persona matters, so a 300-villager voting simulation can legitimately get spread from persona, but its size, direction and independence are unvalidated (no ground truth; confidence is not calibrated to human diversity).
  - Reusable idea: the 11-17% flicker of the top option across identical calls (flat distributions, no seed) is accidental unpredictability concentrated on near-ties; if the lab wants "10-20% error as useful unpredictability", it should generate it from a seeded sampler over P (KITE) rather than rely on API noise, and should log P so that near-tie views can be identified.

## 2610.01834 — Code Owns the Simulation, Jev Owns the Evaluation
- Yaodong Yang, Hongyao Tang, Yi Ma, Xingyu Fan, Weixun Wang, Jinpeng Li, Tianpei Yang (CUHK, Tianjin, others), submitted 1 Oct 2026, https://arxiv.org/abs/2610.01834; read: full text (PDF via pdftotext), accessed 2026-10-08 (appendices not read).
- Systems and readouts tested: Jev 1.13.0, zero-shot, options with text descriptions, returns probability per option; no generative control model in the main comparison (a word-overlap rule serves as a heuristic control).
- Design: (a) 150 Cognitive Reflection Test questions x 4 options x 4 orders, plus control versions; (b) 210 random 3x3 matrix games (depth 0-3 x aligned/misleading, 30 per cell, 3 option orders; conditions plain, "reason", "told" the opponent's action); (c) ALFWorld, single decisions on 116 seen games replayed from the expert, and whole games on 134 unseen games with lookahead; (d) DeepMind Stacker robot control, 20 native episodes and 5 new instructions x 8 seeds. Probabilities averaged over several option orders. Step labels (evaluation-only, simulation-dependent aligned / misleading) computed from the environment, never from model output.
- Key results:
  - CRT (Table 1): correct 0.99 on lure questions (CI [0.97, 1.00]), intuitive 0.01, controls 0.96; humans give the intuitive answer 55% of the time in open form.
  - Games (Fig. 2): dominant action 100%; aligned games 77-93% at all depths; misleading games 28-37% (chance), 53-71% of the time the lure (highest-average-payoff action). Depth has no effect once alignment is accounted for. Telling Jev the opponent's action: 97-99%. A softmax over average payoff fits Jev's probabilities best (a quantal level-1 player). Separately, Jev predicts the opponent's equilibrium action 90% of the time, yet its own choice is correct in 32% when its prediction was right and 35% when wrong; with code writing Jev's own prediction into the state, accuracy in misleading games rises 33% -> 94%, and Jev plays the best response to a wrong written prediction in 24/26 calls (Sec. 4.3, Table 2).
  - ALFWorld: at misleading simulation steps accuracy 36% (seen), lure picked 56% (five times the uniform rate); aligned steps 99%, evaluation steps 93%. With code-run lookahead (each option shows the next observation and newly possible commands) misleading-step accuracy 36% -> 79%, whole unseen games solved 42 -> 116 of 134 (31% -> 87%); a word-overlap rule with the same lookahead solves only 18. Goal-form task wording: Jev's own subgoal prediction is correct only 33% (ordered form 100%). "After" in the wording is not followed (24% vs 69%).
  - Robot control: raw torques 0/20, random 0/20; skills simulated by code 9/20 (hand-written controller 8/20); new instructions 22/40 for Jev vs 3/40 hand-written.
  - Repeating a single call changes probabilities by 0.04 on average (reproducibility note); order shifts Jev's probabilities (protocol averages orders).
- Proposed method or recipe, and its cost: split each decision into code-supplied prediction z (game rules, environment copy, physics, or a prior separate Jev call) and Jev evaluation of options that already contain z. Cost: one or two Jev calls per decision plus the simulator; lookahead cost grows quickly with the number of commands and depth (authors).
- Authors' stated limitations: one model, one API version; the ALFWorld/Stacker simulators are exact copies of the environment; one-step lookahead only; boundary analysis partly post hoc; no test with reasoning allowed.
  My caveats: "simulation vs evaluation" is defined by the authors per task and labelled automatically, but whether a given real decision is of either type is a judgment; a single model.
- Relevance to the lab: items 1 (game work) and 2, and design of item 7. Verdict: **already shows what the lab found (prior/parallel work)** for lures and missing information; **extends** the design of the school simulation.
  - The lab's design (code computes a coarse discrete view; the model only picks a turn) is exactly "code owns the simulation". The paper's lure result matches two lab results: (i) set3's persistent failure, a decisive fact missing from the input while a default is plausible, is a simulation-dependent decision in their sense (the input lacks z), and the model picks the surface-plausible option; (ii) game_test: text naming an option key is followed by every decision model, a surface shortcut in the same family as "options that mention a task word". Also, set6 p2's errors being 95% "hold course" on one redundant branch is the same concentration on a single lure that they report (90% of misleading-game errors on one action).
  - The lab's W2 (sufficiency) class can be read as a detector for "z missing"; the paper's remedy (code states z, or Jev is asked for z in a separate call) is the constructive counterpart that set3/set4 have not tried; it fixes games when Jev can predict z (90%) but not when it cannot (goal form 33%).
  - Reusable ideas: (1) in the school, add a code-computed lookahead field to each turn option (e.g. predicted distance to predator after the move) and test whether the 21% error falls and which branch it moves to; (2) fit a one-parameter softmax over a code-computed shortcut feature (here, "hold course" score) to K27's per-view probabilities: if it fits, that is a cheap surrogate error generator for the lab's own error-structure experiments (random vs view-fixed vs side-biased), and a way to predict which views are error-prone before querying; (3) average over option orders as in their protocol (lab benchmark p3: order reversal flips 21/60 for J).

## 2610.09683 — System Switch: When Should a Fast Decision Model Stop and Think?
- Gianluca Bailo (independent), submitted 7 Oct 2026, https://arxiv.org/abs/2610.09683; read: full text (PDF via pdftotext), accessed 2026-10-08 (appendices not read).
- Systems and readouts tested: zero-shot System One typed-decision models through llama.cpp /v1/systemone: Julia-1 (0.15B), Laya (0.4B; two revisions), Kev (0.8B, 4B, 9B), Lev 4B, Clef-Flash 9B, Strands Decider 2B; task-trained Laya-v3 and doomGemma (Gemma-4-E2B LoRA); "thinkers" Qwen3.6-35B-A3B and Gemma 4 26B-A4B with and without reasoning. (No Kev-27B.)
- Design: Doom (ViZDoom via doomLaya, a rule-based oracle labels states; options attack/collect/open door/exit/retreat/explore/wait, a question every 0.5 s game time). Offline: 900 held-out questions (600 command, 300 weapon) from 42 games, CIs resample games. Deferral: send the actor's least-confident x% to the thinker and compare with random deferral. Closed loop: 33 games, three seeds per variant on MAP01, 180 s each, with a "rule control" that uses the same gate but a fixed explore command.
- Key results:
  - Zero-shot models over-choose "collect" among their errors 1.6-1.8x chance, independent of option order (Table 1); command accuracy 0.14-0.60; order changes accuracy for some (Strands 0.59 -> 0.38 shuffled); task training transfers poorly (doomGemma 0.963 validation -> 0.860 unseen seeds).
  - Accuracy, calibration and sensitivity (AUROC of top probability for right vs wrong) are distinct: five models of accuracy 0.54-0.60 have AUROC from 0.60 to 0.89 (Table 2). The most sensitive actor (base Laya, 0.89) is at chance within category (0.52 [0.40, 0.63]): its confidence tracks which kinds of situation it fails, not which answers are wrong.
  - Deferral (Table 3): deferring the least-confident 30% to the reasoning Qwen3.6 lifts base Laya 0.56 -> 0.75 (perfect selector 0.76; thinker alone 0.69); gain over random deferral +0.15 [0.11, 0.19] for AUROC 0.89, +0.05 for 0.77, and -0.01/-0.02 (no gain) for Kev 9B and Strands (AUROC 0.61/0.60) although they are the most accurate. Rank correlation between actor AUROC and gain over random at 30%: 0.87 over 18 actor x option-order pairs. With actor and rate chosen on held-out games the gain is +0.13 [0.08, 0.18] (fixed order) and +0.08 [0.02, 0.14] (shuffled); advantage over the better of actor and thinker alone is +0.05 [-0.12, 0.11] (not shown). Reasoning carries about half the gain (without reasoning +0.07, thinker shares the bias: 97% of errors choose collect).
  - Closed loop (Table 4): no variant reaches the exit (33 games); committing to plans, whether the thinker's or a fixed explore rule's, covers more map (64-83 cells vs 61-77) and opens more doors (8-9.7 vs 5); the rule control matches the thinkers on coverage and dies more (2.7 vs 1.3 deaths/game; with base Laya 3.7 vs 0.7). Base Laya alone stands still (1 cell) but plays once a gate adds commitment. The thinker takes ordinary doors for locked ones (17/25 failures conclude "needs a key"); thinking occupies 38-70% of game time on frames 9-29 s old. Offline accuracy and closed-loop behaviour measure different things because the oracle never labels explore.
- Proposed method or recipe, and its cost: choose the fast actor by AUROC within the relevant category, not by accuracy; gate on uncertainty and progress signals; let a plan commit until done. Cost: about 29 ms per actor decision; the reasoner writes a median of 1,300 tokens per decision, so deferring 30% is not feasible in real time.
- Authors' stated limitations: accuracy is agreement with a one-policy oracle; fixed option order affects some results; headline actor and rate selected on the test set; small closed loop (3 games per variant, deaths may be noise), no exit.
  My caveats: small models (0.15-9B) and a toy oracle; the deferral claim is about relative gain over random deferral, and the paper itself says the robust result is not that the combination beats both components.
- Relevance to the lab: items 4/8 (set4 verification methods, margin gates) and item 7. Verdict: **already shows what the lab found (prior/parallel work)** for failed confidence gating; **new idea** for gate selection; **background** for the closed loop.
  - Deferral gain proportional to AUROC: if the confidence has no within-category discrimination, gating equals random review. This is the lab's set4 observation (unanimity-or-review no better than random review; 3-model vote worse) and why blind verification caught only conflicting-records errors. It also predicts which of the untried set8 countermeasures (margin-based gates) can work: only if K27's top-probability or margin has AUROC above 0.5 for right vs wrong *within* each workload class (W1/W2/W3 and the missing-evidence subclass); an overall AUROC would mislead because classes differ strongly in accuracy.
  - "Over-choose one option class by 1.6-1.8x chance regardless of position" parallels the lab's school finding (errors collapse on hold-course) and set3 (default option when evidence is missing): systematic option-class bias, not random error, is the typical decision-model error. Bias of this type can be tolerated in an aggregate when the option is redundant and is dangerous when it is the lure.
  - Closed-loop failure: offline match to an oracle did not predict closed-loop behaviour, and a trivial fixed-command rule behind the same gate did as well as the thinker. Direct analogue for set6 p2: always include a trivial/rule control school and judge on collective outcome, not on per-decision accuracy (which the lab already does).
  - Reusable idea: compute the within-category AUROC of K27's P(top) and margin on the set3 core 200 cases (class = workload or fallback type); only gate on margin if within-class AUROC is clearly above 0.5.

## 2610.09188 — From Probabilities to Decisions: Search and Multi-Teacher Distillation with Jev
- Mohamad Yazan Sadoun, Sarah Sharif Yaser, Mike Banad (INQUIRE Lab, Univ. of Oklahoma), submitted 6 Oct 2026, https://arxiv.org/abs/2610.09188; read: full text (PDF via pdftotext; two-column layout interleaved, so I read Sec. 1-5 and spot-checked appendices), accessed 2026-10-08.
- Systems and readouts tested: Jev 1.13 pairwise "which move is better" probabilities (both presentation orders averaged); Qwen3-32B, OLMo and DiffusionGemma as other judges; reranker experiments with Jev vs Qwen.
- Design: bullet chess: a bot with Stockfish search + opening book + tablebases + a 411-weight evaluator trained from Jev (Lichess 1753 -> 2268 over 100 games vs bots). Controlled study: fixed search, evaluator = Bradley-Terry fit of a 443-weight linear score to judge probabilities on 63,135 candidate pairs from 13,000 positions; 252,540 responses per arm; matches of 2,000-4,000 games on fresh openings, bootstrap over opening clusters. Passage reranking: MiniLM reranker on BM25 top candidates, 5 seeds.
- Key results:
  - Live Jev call 177 ms; using Jev only to break ties in search lost 28.7 Elo [-51.1, -6.6]. A distilled evaluator adds 38.9 Elo [29.9, 47.9] over a mobility baseline.
  - Jev+Qwen (average of the two judges' probabilities) beats Jev on twice the pairs by +27.0 Elo [19.2, 34.8] and Qwen on twice the pairs by +8.0 [0.9, 15.3] (Table 1; pooled +9.6 [4.3, 14.9] over 4,000 games, then +8.4 on a further 4,000). Two answers from the same judge averaged is no substitute: Jev (its two answers agree on 92.1% of pairs) +28.2 Elo gap, Qwen +14.3 (Table 1). Replacing Jev with 0.5 or shuffling it: +9.6/+10.9 gap, stricter within-group shuffle only +5.3 [-0.5, 11.0] (Table 2). Partner choice: Jev+Qwen leads OLMo+Qwen and DiffusionGemma+Qwen by +16.6/+16.9 (full-data) but only +7.7/+7.9 when the regulariser is reselected per subset, and the lead over Qwen-on-twice-pairs drops to +2.2 [-2.4, 6.8] under that rule.
  - Label-level accuracy is a poor guide: agreement with Stockfish preferences is 54.5% (Jev), 52.9% (Qwen), 53.4% (OLMo), 54.4% (DiffusionGemma); Jev and Qwen disagree on 30.9% of pairs; on those, Jev matches Stockfish 53.6% and the average only 48.2%, yet the averaged labels train the stronger player. Jev has the lowest ECE (0.081 vs 0.159-0.260).
  - Reranking: Jev's labels alone give a reranker equal to Qwen's (difference +0.008 [-0.007, 0.022]); adding Qwen gains at most +0.004 [-0.003, 0.011]; Jev took 21 min of API calls vs 5.1 GPU-hours for Qwen.
- Proposed method or recipe, and its cost: label offline, distill to a small evaluator, use it inside search; combine a decision model with an LLM by averaging probabilities before fitting. Cost: about 250k judge responses per arm; no live calls at play time.
- Authors' stated limitations (partly in appendices, not read): gain depends on regularisation choices; improvement is a few Elo; applies to chess/passage ranking with one second judge family; the best result was chosen on test data (see per-subset rule).
  My caveats: the headline "second answer from the same judge is no substitute" compares two near-identical Jev answers (92.1% agreement), i.e. an almost deterministic API; it does not test a *prompt-varied* second answer from one model, which is what set6 p1 tested.
- Relevance to the lab: items 4 and 6. Verdict: **already shows what the lab found (prior/parallel work)** for "same model twice adds nothing"; **partly contradicts** set4's majority result in a different regime.
  - Consistent with set6 p1 (24 persona agents = 1.0 vote; 7 different models = n* 3.4-5.6) and set5 (re-asking a one-pass scorer): a second sample from the same deterministic judge carries almost no information; a different model does. The difference to the lab: they average *probabilities* of two judges into soft labels for a learner that regularises (gain 10 Elo, fragile to reselection), and the gain exists although the average is *less* accurate against the oracle on disagreements. The lab's 3-model hard-vote on W3 got worse; the two are not contradictory (hard majority of three systems sharing missing-evidence errors vs soft average feeding a smoother) but show that a vote's value depends on error independence, not on accuracy per label.
  - Reusable idea: in a school or village of deciders, assign each agent a *model* as a trait (K27, W12, A27 ...) and average or sample from the soft probabilities of two models instead of repeating one; test whether collective accuracy beats a one-model school (the lab already has the n* numbers). Also a reminder that agreement with the oracle at label level need not rank systems by their effect on the final behaviour; evaluate at the collective level, as set6 p2 does.

## 2609.37009 — An LLM-powered Agent Framework for Heterogeneous Evacuation Behavior Modeling under a Moving Threat in a Public Plaza (adjacent; generative LLM, not a decision model)
- Jian Ma, Runxin Yu, Tianyu Tang, Xiaolian Li (Southwest Jiaotong Univ.; Fujian Police College), submitted 29 Sep 2026, https://arxiv.org/abs/2609.37009; read: full text (PDF via pdftotext), accessed 2026-10-08 (methods and results read, related work and appendices skimmed).
- Systems and readouts tested: GLM-5.3-flash as decision and memory model, temperature 0.2, lowest reasoning level for ordinary decisions and high for decisions triggered by direct visual evidence. No Jev or decision-model readout.
- Design: public plaza with 3 exits and a moving threat; each simulation has 11 pedestrians; 8 personality compositions of the 11-person group (5 homogeneous: average, calm-independent, bold-solitary, rule-following, anxious-conformist; plus mixed) in 8 paired randomized blocks; 704 pedestrians, 10,947 decision epochs. Agents get a private ASCII view and a memory knowledge graph updated only from own observations; a validation engine executes routes only over observed terrain. Paired sign-flip tests with Holm correction; logistic and linear models on evacuation outcome and time.
- Key results: 462/704 pedestrians evacuated (65.6%), 202 killed (28.7%). - Proposed method or recipe, and its cost: persona-conditioned LLM agents with symbolic views, memory and an engine that owns physical feasibility. Cost not stated in the parts read; the LLM is called per pedestrian decision (an LLM-call cost the lab's decision models avoid).
- Authors' stated limitations: small pedestrian population in one plaza under a specified threat policy; personality enters both prompts and the affect model so effects are for the combined configuration; no human comparison yet.
- Relevance to the lab: items 6 and 7 as background. Verdict: **background only**, with one useful pattern.
  - Persona heterogeneity shows up when evidence is ambiguous and vanishes when evidence is strong: same shape as set6 p1 (evidence dominates persona, n* about 1) and 2609.36399 (persona is a weak, diluted signal). Information in the view (known exit) explains 89.5% vs 1% outcomes, far more than personality.
  - Scale is 11 agents/run, so it says nothing about 300-agent collectives; the same feasibility-engine split ("choice decoupled from physical feasibility") is the "code owns the simulation" design again.
  - Reusable idea: define the villager persona effect as an interaction with evidence strength: measure spread of votes separately for ambiguous and decisive proposals, expecting spread only in the ambiguous bin.

## Cross-paper notes

### What has already been done in this space
- Query once per unique state, run populations from a table, event-keyed random numbers, shared model-human discrepancy (KITE, 2609.27535); the lab's view cache is a coarse-view version of this.
- Large decision-model populations on an election task: about 330,000 voters, state calls roughly as good as generative agents, shares twice as wrong, systematic partisan lean (JEVal, 2610.03935). Individual-level survey prediction at 38-40% accuracy at about 0.5-8 s per item.
- Decision models fail at per-step simulation and succeed at evaluation; code lookahead fixes it (2610.01834); fast chooser + persistent planner (2609.27331); confidence gating pays only in proportion to AUROC, and committing matters more than thinking in the closed loop (2610.09683); a second answer from the same near-deterministic judge adds nothing, a different model does (2610.09188); persona text moves answers in a stereotyped, diluted way and API repeats are near-identical (2609.36399).
- Persona heterogeneity in LLM populations appears under ambiguity and disappears under strong evidence (2609.37009).

### What is still open, and what the lab's set6 line could claim
1. Effective number of votes for a population of one model, measured against ground truth (n* = 1.0, mutual-error agreement 0.90-1.00, flat majority accuracy; and n* 3.4-5.6 of 7 for a mixed-model panel). None of the eight papers measures this: KITE shows flat curves in persona count for effect error and 19.4% shared error across model tiers; JEVal averages P(Harris) without testing independence.
2. Error structure versus collective outcome: the lab's school result (21% wrong vs the rule, collective indistinguishable; random view-fixed or side-biased errors worse; 95% of errors on a redundant branch) is, as far as these papers go, the only direct test that the *form* of a decision model's errors decides whether a collective tolerates them. KITE gives the theory (shared error does not shrink with N) but for human-referenced effect sizes; JEVal and System Switch observe systematic option-class bias (partisan lean; 1.6-1.8x over-choice of "collect") but do not intervene on its structure.
3. Aggregate versus conjunctive tasks: the same per-decision error costs 11 points in a 13-step tau-bench trajectory but nothing in the school. A short statement of when each regime applies (redundant branch, aggregate statistic, no single agent's trajectory matters) would be a clean claim.
4. Where unpredictability should come from: Jev-style models are nearly deterministic across calls (ICC 0.997; 0.04 mean probability change), have no seed, and are overconfident (89% on the mode vs 35% true), so sampling from raw P gives little spread while the model's own errors are systematic, not random. A "10-20% error adds useful unpredictability" claim has to separate (a) seeded sampling from a calibrated P, (b) argmax plus structured model error, and (c) a mixed-model panel. Nobody has compared these.
5. Missing-evidence views and persona populations: papers 2610.01834 and 2609.37009 are consistent with the lab's set3 finding (model decides anyway when a decisive fact is absent), and the lab's fallback classes (missing_evidence, conflicting, explicit_defer) have no counterpart in these papers.

### Design ideas for a 300-villager voting or 300-fish simulation
- View table: define the villager's decision through a finite view (proposal facts, private stake class, a binned summary of neighbours' announced leaning, rounds left). Query once per unique view (as in set6 p2 and KITE), keep the full probability vectors, and run the 300 agents from the table.
- Randomness: per (seed, agent, round) uniform variate used to invert the table's CDF (KITE); use common random numbers for counterfactuals (change the proposal or a stake and re-run with the same variates). Calibrate temperature on the rule villagers first, since raw P is overconfident.
- Three variants to compare against a code-defined rule villager (threshold or Granovetter-type rule with a known analytic outcome): (a) sample from calibrated P; (b) argmax of the model (21%-style structured error); (c) same-model persona agents. Add (d) mixed-model agents (K27, W12, A27 assigned per villager as a trait) and (e) injected controls: random view-fixed errors and per-agent side bias of the same size. Pre-register an equivalence margin on the vote margin and on time to consensus.
- Report both expectations (conditional expectation over the table, no draw noise) and a run-level shared-discrepancy term (a draw once per run, not per agent), so the claimed uncertainty reflects model error rather than N.
- Stress the regime where error matters: tipping-point margin near 50% (state calls vs shares in JEVal) and cascade/thresholds, where per-agent error is amplified; check whether an 80-90% accurate decision still gives the same outcome distribution there, and add a landslide case as a negative control.
- Add a lookahead field per option (2610.01834) and a "unknown / need more information" option with a code-controlled view so that missing-evidence defaults do not enter as silent votes.
- Persona effect should be measured only as an interaction with evidence strength (ambiguous vs decisive proposals), following 2609.37009 and 2609.36399; do not expect independent spread from persona strings on decisive questions.
- For gates or review in the loop (e.g. send low-margin villager decisions to a larger model), first compute within-class AUROC of K27's margin (2610.09683); a gate with AUROC near 0.5 inside a class equals random review.
- School specifics: anchor calibration is cheap because the rule is the oracle: evaluate it on a small subset of views and tilt only if a mean bias appears (a side bias), not for hold-course errors.
