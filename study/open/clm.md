## Summary
Not a decoder fine-tune but a dual-encoder: a frozen Qwen3-8B embedding backbone plus two small trained projection heads (state head, action head; ~9.4M each per OpenJev's table, "20M" per CLM's README), trained with a bidirectional InfoNCE contrastive loss. A typed question is a state plus a closed set of candidate actions; softmax over dot products is the answer distribution. Claims parity with Jev on computer-use/game/tool tasks with up to 9x lower latency.

## Approach / architecture
- State and each option embedded separately (last-token pooling from Qwen3-8B served by vLLM `--runner pooling`); state head and action head project to a shared space; score = dot product (learned logit_scale). Action embeddings are cached and reusable across states; vector cache reserves GPU memory (default 2%).
- Not non-autoregressive in a "slot read" sense; it is an embedding scorer, so Choice options and Score levels are candidates scored against the state. States limited to 2,048 tokens by default (raise `--max-model-len`).
- Calibration: no separate procedure documented in the README beyond the softmax with a learned logit scale; I did not find a temperature-fitting recipe (docs/FINETUNING.md search for 'temperature/calib/ECE' returned nothing).

## Interface
`clm-serve` on :8700 with `POST /v1/systemone`, `/v1/models`, `/health`, TypeSafe-style `CLMClient` with Choice/Noul/Score, playground UI, `engine.rank()` for free-form candidate ranking (best-of-N). Up to 255 options. Requires a vLLM embedding server for Qwen3-8B.

## Training & data
Three stages with InfoNCE: (1) pre-train on ~60M Nemotron DQA question-answer pairs (question=state, answer=action); (2) mid-train on ~30M synthetic hard negatives generated by Gemini 2.5 Flash-Lite (a closed teacher), using a hard-negative-augmented state-to-action InfoNCE; (3) post-train on ~1M agent trajectory steps (Agent Data Protocol, Endless-Terminals, LiteCoder-Terminal-SFT) with 40% Nemotron replay. Ablation: pre-train only 52.1% top-1 on 100K held-out questions with 10 hard negatives each; +mid-training 69.2%; hard negatives from the start peaks at 62.4%. Scaling laws: test InfoNCE falls as a power law in compute, data, head size and encoder size; optimal head size ~310 training tokens per parameter. Fine-tuning scripts and a `LocalLLaMA/typed-decisions` workflow exist; DeepSWE/Terminal-Bench verifier heads released as HF datasets. No RL, no RLCD.

## Reported performance
Author claims (charts, not tables in README): on-par with Jev on T-Rex, BFCL v4 tool calling, WikiRacing and Super Mario with up to 9x lower latency; as a verifier after light fine-tuning 81.6% on 38 held-out DeepSWE tasks (31/38) and 87.6% on 30 held-out Terminal-Bench 2.1 tasks, 4.1-5.7x faster than Jev, while Jev scored below pass@1 as a verifier (candidates sampled from "Opus 5" and "Fable 5"). Server p50 ~28 ms for a new state on an RTX 4090 (cached states 0.6-1.7 ms). Small eval sets; not third-party verified. Text typed-decision accuracy/calibration on standard decision benchmarks is not reported in the README; the generic head quality for Noul/Score semantics is therefore unknown.

## Self-hosting notes
Needs a GPU for Qwen3-8B embeddings (vLLM) plus a CPU-light `clm-serve`; 75 MB reference head downloaded on first run.

## Assessment
Different architecture family (contrastive retrieval) that is excellent for action selection among many candidates and verifier use, with real cache-driven speed advantages. Weak spots: no demonstrated calibration or typed-score fidelity; Noul/Score are awkward fits for an embedding scorer; relies on a closed model (Gemini) for hard negatives. Useful to the lab as the main non-generative-head alternative to LoRA-on-decoder recipes.

## Independent arXiv evidence (added 2026-10-08)
A preregistered judge evaluation (2610.07177, same author as the Laya reproduction) found CLM-v0.1-8B near chance on hard public judge benchmarks:

- 0.351 best-of-four (chance 0.25);
- 0.593 pairwise (chance 0.5);
- one constant label on HaluEval.

Raw confidence is overconfident by up to +0.401, and a pooled temperature repairs ECE to ≤0.062. Two properties do work:

- the order-flip rate is 0.0002, against 0.2188 for a generative judge;
- the length bias is small.

A confidence-gated cascade still escalates 92–100% of items at the preregistered retention bar, so calibrated confidence about a weak judge saves nothing. COGNIT-Guard (2609.33671; abstract) uses a domain CLM-8B as a baseline. See [../recent_study/evidence/second-pass-and-cascades.md](../recent_study/evidence/second-pass-and-cascades.md).
