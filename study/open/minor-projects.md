# Minor / thin open projects (retrieved 2026-10-01)

All facts from each repo's README and GitHub metadata unless stated.

## LocalJev (githubnext/localjev)
TypeScript/Bun, MIT, ~806 stars, created 2026-09-18, one day of activity (last push 2026-09-18). A Jev-compatible `POST /v1/systemone` bridge in front of any OpenAI-compatible chat endpoint (default oMLX serving `diffusiongemma-26B-A4B-it-4bit`). Crucially it does **not** read logits: it prompts the model to emit a JSON probability scalar/vector, validates, retries malformed output (`LOCALJEV_MALFORMED_RETRIES`, default 2), normalises, and computes choice / expected score / entropy confidence. The README itself says this is "wire-compatible, but not mathematically equivalent to OpenJev's logit read" and that probabilities are "generated/self-reported" and need calibration checks. Accepts `jev-latest`/`jev-preview` aliases; works with the TypeSafe SDK. Includes a 1,200-request bake-off on AG News / BoolQ / SST-5 across five installed models on an M5 Max (report in `docs/evaluation-results-2026-09-18.md`, not read; README says Gemma 4 26B-A4B and Qwen3.6 were strongest in a "small screening sample"). Notes that the normal oMLX/LM Studio APIs lack seeded canvases, read-only denoising and token logprobs for DiffusionGemma. Relevance: a counter-example showing a wire-compatible but non-logit implementation.

## djev-run (taeold/djev-run)
HTML/Docker, no license declared, ~575 stars, created 2026-09-20, last push 2026-09-24. Packaging of `mmastrac/djev` (Apache-2.0, 110 stars, "Jev-style structured decisions on DiffusionGemma: the example server from vLLM PR 57250") for Google Cloud Run with an RTX PRO 6000 Blackwell GPU, plus demos (/snake, /dino, /tetris). Image `ghcr.io/taeold/djev-run:latest` serves vLLM `nvidia/diffusiongemma-26B-A4B-it-NVFP4` with `diffusion_read_only`, `diffusion_max_steps: 1`, pinned canvas positions and a `/v1/systemone` endpoint (response includes `diagnostics.timing`; note the sample response returns `confidence` equal to the top probability, which differs from the entropy-based formula used by openjev, razorback16). Author-reported: cold start ~47.5 s (from 4 m 05 s), 61 ms server / 117 ms end-to-end median (`steps=1, samples=1`), 100-123 req/s at concurrency 32; JevBench v1.3.0 (N=231 public suite, benchmarkheaven.com) overall accuracy 81.4% (composite 73.4) at `steps=1,samples=1`, 81.8% with `samples="auto"`, versus `api.djev.dev` 81.8% / composite 73.0 at 237 ms. These JevBench figures are the repo's claims; the benchmark site was not independently checked. Cost: $3.19/hour while active on Cloud Run, scale-to-zero.

## Deqio (ILuce/deqio)
Python, MIT, ~6 stars, created 2026-09-23, last push 2026-09-29. Local multi-engine runner and browser UI: one API (`POST /v1/noul`, `/v1/choice`, `/v1/shared`; not `/v1/systemone`) in front of switchable decision models, installed through `deqio models setup` in isolated runtimes (MLX, MPS, CUDA). Catalog bundles SemIf/Qwen3.5-4B (the only plainly training-free entry), plus trained or community models: Kev 0.8B-27B, JevK5, Open-Jev, CLM 8B, Decider 0.8-4B, Laya (English, Multilingual, Typed Decisions), Von, Bespoke Nimble 9B v2. Author benchmark on `deqio-basic-150` (150 requests / 250 decisions, 16 GiB Apple Silicon, 2026-09-26, single local run): Decider 4B (MPS) 95.3% case accuracy / 97.2% decision accuracy at 436 ms median; Kev 4B (MLX) 92.7% at 318 ms; SemIf/Qwen3.5 4B 90.7% at 552 ms; Laya Typed Decisions 421M 62.0% at 34 ms; Laya Multilingual 322M 44.7% at 13 ms. The benchmark set is the project's own and not shared with anyone else; authors caution against universal rankings. Relevant mainly as a comparison harness and model catalog; it does not do its own scoring.

## jev-visual (hr98w/jev-visual)
Python, MIT, ~303 stars, created 2026-09-17, last push 2026-09-21. Educational Jev-like inference for images on Apple Silicon: Qwen3.5-0.8B-4bit with MLX; image + context -> shared multimodal prefill -> fork KV/recurrent-state cache -> batched question suffixes -> read candidate scores from the LM head -> assemble typed answers in code. Choose / yes-no / ordered-level questions via browser UI, CLI and HTTP API (own API; `/docs`, no `/v1/systemone` mention). Runs on M4/16 GB with ~596 MiB of weights. Demos: sorting factory, Breakout, camera gestures, 2x2 cube (the model "cannot reliably solve" it). Honest limitations: Breakout only works after simplifying to "which of five regions contains the ball" (80 decisions: 9 bricks cleared, 6 returns, test stopped before completion); no accuracy or calibration numbers; says it does not reproduce Jev's architecture, RLCD training, calibration or serving. Relevance: only vision-capable training-free example in this batch besides razorback16/openjev (DiffusionGemma images) and litjev (screenshots).
