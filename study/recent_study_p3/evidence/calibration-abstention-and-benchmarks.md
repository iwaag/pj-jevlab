## 2610.19811 — Calibration and Risk-Budgeted Decisions with System One Models
- Authors: Soundouss Messoudi (Heudiasyc, UMR CNRS 7253, Université de Technologie de Compiègne), Youness Mansar (independent researcher, France); v1 dated 14 Oct 2026; https://arxiv.org/abs/2610.19811; read: full text, accessed 2026-10-19. Independent of the vendors (all five hosted systems are tested through standard commercial access). The authors fine-tuned one model they rank (Kev-ft, from Palmer's open Kev-0.8B); they did not build Jev or the other APIs.
- Systems and readouts: hosted Jev (typesafe/jev-1.13), GPT-6-Luna (OpenAI typed-decisions endpoint), Span-01 (Respan), Solar-Decide (Upstage); open Kev-0.8B as released (Kev-base) and after fine-tuning (Kev-ft; rank-16 LoRA plus 256-dim pointer head on a frozen Qwen3.5-0.8B-Base backbone); baselines Qwen3Guard-Gen-0.6B (softmax mass on "Unsafe" tokens), Voyage rerank-2.5-lite (score clipped to [0,1]), and PCA-Ridge (logistic regression on frozen Qwen3-8B embeddings, 100-dim PCA, fit per dataset). All are used as a binary score s(x) in [0,1]; only binary tasks. No letter-logit or pointer model other than Kev (pointer head).
- Design: not pre-registered (none stated). Six datasets: WildGuardMix, Aegis (moderation), S-Labs prompt injection, ATBench agent trajectories (safety), SciDocs and StackOverflow (reranking as binary filtering). Single seed, label-stratified fit/calibration/test splits (Table 1; test sizes 850, 579, 1050, 250, 1000, 1000; fit 2000 except ATBench 500; positive rate 44.4% to 67.0%). Three threshold rules compared at risk budgets alpha in {0.05, 0.10, 0.15, 0.20, 0.40, 0.50}: Naive (tau = alpha, assumes exact calibration), Empirical (lowest-FPR tau whose calibration false omission rate (FOR) is at most alpha), and Learn Then Test (LTT, delta = 0.10, fixed-sequence binomial test, candidate grid from up to 200 fit-score midpoints plus endpoints, support floor of 25 calibration examples). Action 1 (block/retain) is the forced fallback; there is no abstention action. When LTT finds no certificate it returns "non-deployment" and the system falls back to Action 1. Primary risk = FOR = P(Y=1 | Yhat=0); utility = true negative rate (TNR). 47 model-dataset pairs with defined settings. Bootstrap 95% CIs (1000 resamples) in an appendix.
- Key results (measured):
  - Calibration is task-dependent (Table 2): Jev ECE 0.034 on WildGuardMix, 0.183 on Aegis, 0.185 on S-Labs, 0.076 on ATBench, 0.29 on SciDocs, 0.099 on StackOverflow. Jev AUROC 0.963 / 0.936 / 0.947 / 0.768 / 0.917 / 0.790 on the same six. Jev Brier on ATBench 0.200.
  - Low ECE does not imply usable discrimination (Sec. 6.1): on StackOverflow Kev-base ECE 0.051 vs Kev-ft 0.16, but AUROC 0.599 vs 0.81.
  - Threshold policies, all 47 pairs x six budgets (Table 3): Naive exceeds the budget in 105 of 250 evaluable settings (42.0%), mean excess 7.09 pp, max 73.26 pp (alpha = 0.05); 32 settings have undefined test FOR. Empirical exceeds in 108 of 209 (51.7%), mean excess 1.17 pp, max 8.57 pp; 73 settings have no feasible policy. LTT exceeds in 12 of 153 (7.8%), mean excess 0.10 pp, max 3.47 pp; 129 settings return non-deployment. LTT certificates at alpha = 0.05 exist for 21.3% of policies and at alpha = 0.5 for 76.6% (Sec. 6.2). The abstract's "roughly half" for naive baselines lumps Naive (42.0%) and Empirical (51.7%).
  - Table 4 (alpha = 0.15, test FOR/TNR %): Jev on WildGuardMix Naive 3.3 / 68.7, LTT 12.8 / 96.8; Jev on Aegis Naive 20.8 / 83.8 (over budget), LTT 11.7 / 67.0; Jev on S-Labs LTT 10.2 / 79.0; Jev on ATBench Naive 33.3 / 3.1, no LTT certificate; Jev on SciDocs Naive 22.8 / 90.9, LTT 13.7 / 76.8; Jev on StackOverflow LTT 16.6 / 44.3 (over 15% budget, though within the LTT guarantee as a test estimate). Span-01 on Aegis Naive 60.9 FOR at 95.3 utility. At alpha = 0.15 Span-01 and Solar-Decide have no LTT certificate (ND) on every dataset in Table 4 (Span-01 on S-Labs, SciDocs, StackOverflow, ATBench, WildGuardMix, Aegis; Solar-Decide likewise); the text says these two fail entirely.
  - Adaptation (Sec. 6.3): at alpha = 0.15 Kev-base gets an LTT policy on one of six datasets, Kev-ft on all six; across all budgets 13/36 to 31/36 settings. On WildGuardMix LTT utility Kev-base 41.9% vs Kev-ft 82.5% vs Jev 96.8% vs Qwen3Guard 95.1% vs GPT-6-Luna 92.6%. On ATBench Kev-ft LTT 14.6 / 89.3 while Jev has no certificate.
  - Cost/latency (Table 5, USD per 1k examples, ms): Jev 0.0216 / 383 (WildGuardMix) and 0.0757 / 261 (ATBench); GPT-6-Luna 0.0375 / 320 and 0.1507 / 294; Kev-ft 0.0030 / 98 and 0.0074 / 241; PCA-Ridge 0.0026 / 5247. Local cost assumes $0.11 per GPU-hour; recorded historical timings, not controlled microbenchmarks. Kev-ft recipe: about 10k pooled examples (9,988 records), 37 minutes on an RTX 5090.
  - Proposition 1: R(tau) = E[S | S < tau] + E[m(S) - S | S < tau], so FOR is bounded by tau plus the mean calibration error inside the selected region; global ECE is not a substitute.
- Method/recipe and cost: hold out a labelled calibration set independent of the fit data; sort candidate thresholds; run the fixed-sequence exact binomial test; if no threshold is certified, take the fallback action. Minimum support to certify with zero errors is ceil(log delta / log(1-alpha)): 45 examples at alpha = 0.05, 22 at 0.10 (delta = 0.10). Needs labelled calibration data per task; no model training.
- Limitations (authors): guarantee needs i.i.d. calibration and deployment data (no adversarial or distribution shift); six English benchmarks; ATBench is retrospective classification of truncated trajectories and reranking uses a constructed document mixture; exact binomial certification needs large calibration sets when alpha is strict, so LTT often returns non-deployment; Kev-ft needs labelled data and compute; no contamination guarantee for external APIs. My caveats: single seed and one split per dataset, so the 7.8% exceedance rate is across settings of one split, not across calibration resamples; the guarantee is per-calibration-draw probability 1 - delta, and the observed exceedances (12/153) are test-sample estimates; the same Dfit builds the threshold grid and trains Kev-ft and PCA-Ridge, so the "adaptation" comparison favours the models trained here; the paper does not vary option names, option order, or evidence, so it says nothing about label or order effects; binary forced action with no true abstention head (abstention is replaced by a fallback action); the "Naive" rule tau = alpha is a strawman for a vendor claim of calibration.
- Relevance to the lab (missing evidence/abstention/fallback, calibration, cascades): Verdict: extends / parallel to the lab's calibration and fallback concerns; prior art for "no abstention, take the conservative fallback" and for deciding when a score is trustworthy. Hosted Jev's ECE moves from 0.034 to 0.29 across datasets, so a single calibration number is not portable; this supports the lab testing calibration per task and per system rather than from vendor claims. LTT offers a label-based, finite-sample way to pick the abstain/fallback threshold for any lab system (K27, W12, A27, J, G) given a calibration split, and a non-deployment outcome is itself the answer "cannot certify". Not covered: multi-option scores (binary only), missing evidence, option naming or order. The paper names LTT extension to multi-model cascades as future work.

## 2610.18579 — Reading Right, Acting Wrong: Diagnosing Decision Failures of System One Models in Agent Loops
- Authors: Yubo Li, Ramayya Krishnan, Rema Padman (Carnegie Mellon University); v1 dated 13 Oct 2026; https://arxiv.org/abs/2610.18579; project website https://yubol-bobo.github.io/System_one_model_evaluation; read: full text (main text and parts of the appendix on protocol, latency and label audits; other appendix tables skimmed), accessed 2026-10-19. Independent academic group; no vendor affiliation; they built the benchmark, not a decision model to rank. A Li et al. 2026 paper cited in related work is an earlier Jev-as-judge study (same first name; I did not verify it is the same author).
- Systems and readouts: 17 fast systems plus a reasoning reference. Hosted: Jev 1.13 (native distribution), OpenAI Decisions (public beta). Open-weight System One models: Clef-27B (native schema head), Kev-9B (pointer head), CLM-8B (two-tower head), Laya (encoder, 512 input tokens), Eikos-27B (letter readout), Perplexity Decider-27B (readout head), SimpleJev-27B (pointer head), Vega-27B (Decision 2.0 runtime), Torchcast-27B (letter readout), Quyet-1.0-Large (letter readout, refuses more than ten options). Readouts of a frozen LLM: Cygnet (grouped letter probabilities), Decider-chat-31B (letter readout). LLM likelihood readouts, thinking off: Gemma-4-31B, Qwen3.8-27B, Qwen3.5-9B (complete-option likelihood). Reference: GPT-6.1 Sol (medium reasoning, one call per question with verbalized distribution). Each system uses its authors' code and defaults except stated input budgets; some systems cut or refuse long states and these count as wrong with coverage reported.
- Design: not pre-registered. A "hash-sealed" manifest freezes every request byte, option order and label before analysis. Frozen benchmark of 65,228 records (59,234 test, 5,994 dev); 19,663 paired test states from ALFWorld, BabyAI-Text, TextWorld (exact simulators), tau2-bench airline/retail, tool use, web navigation and coding traces. Each state has a next-action question (all admissible actions in context, with name and description, none shortlisted) and independent factual probes answered separately. U = all measured facts correct; D = decision correct; four cells U1D1, U1D0, U0D1, U0D0. Model-free sufficiency criterion for probes (intersection of gold sets non-empty). Follow-ups: composition ladder on 1,200 generated states (Sec. 6.1), probe-then-decide on 2,783 real states (Sec. 6.2), decision-oriented probes on 644 ALFWorld states (Sec. 6.3), controlled variations (Sec. 7). Label audits: an independent content audit flagged 98 test records (kept, sensitivity analysis: no group score of any system moves by more than 3.5 points); an ALFWorld location-label problem on 303 of 8,197 paired records. Bootstrap CIs for follow-up gains.
- Key results (measured):
  - Table 2 (decision accuracy D on 19,663 paired states; share of errors made with all facts right): Jev 0.763 (73.1%), OpenAI Decisions 0.706 (70.3%), Eikos-27B 0.795 (77.7%), Clef-27B 0.777 (76.0%), Vega-27B 0.748 (58.0%), Perplexity Decider-27B 0.723 (62.3%, coverage 90.7%), Torchcast-27B 0.678 (78.7%), Kev-9B 0.626 (49.2%), SimpleJev-27B 0.592 (67.6%, coverage 93.4%), Cygnet 0.683 (77.6%), Decider-chat-31B 0.719 (62.0%), Gemma-4-31B 0.811 (80.9%), Qwen3.8-27B 0.793 (78.0%), Qwen3.5-9B 0.569 (55.6%), GPT-6.1 0.884 (85.2%). Laya 0.166, Quyet-1.0-Large 0.129 (coverage 3.8%), CLM-8B 0.123: low because of input limits counted as wrong.
  - For the six most accurate systems 73-85% of decision errors occur when every measured fact is right (Sec. 5.1); given all facts right the action is still wrong in 10-21% of states; given at least one fact wrong the action is right in 62-70%. The share rises with accuracy (49% for Kev-9B to 81% for Gemma; 85% for GPT-6.1).
  - Errors cluster on states (Sec. 5.3): of 53,382 facts-right/action-wrong events from the 14 competent fast systems, 56% fall on states where at least seven of 14 fail (null 16%); all 14 fail on the same 141 states (null expects none); GPT-6.1 gets 40% of those 141.
  - Cost of errors (Sec. 5.2): most errors cost at most one extra step (86-90% in ALFWorld, 42-56% BabyAI, 77-84% TextWorld); 5-42% of a system's "wrong" simulator decisions are optimal under exact lookahead.
  - Composition ladder (Sec. 6.1, 1,200 generated states): Jev reads rule facts at 100% and decides 1.000 from facts alone but 0.791 from the raw trace (gap 21 pts); 0.974 with correct facts appended, 0.751 with irrelevant facts appended. Qwen3.8-27B 0.797 / 0.994 facts only. SimpleJev-27B gap 45 pts (0.551 trace). Jev's 251 raw-trace errors: 125 precedence, 103 distractor, 23 default. Rewrites: neutral wording +0.5 (Jev), evidence last +7.9 to +10.8, removing distractors +7.8; only a summary in one place recovers the facts-only level. Clef: removing distractors alone +33.2.
  - Using the model's own fact answers (asked separately): Jev 0.791 to 0.968 (+17.7), Qwen3.8-27B to 0.955, Vega-27B +19.9, SimpleJev-27B +27.6; GPT-6.1 gains nothing (0.928 to 0.931). Composing the action in code from the model's own fact answers reaches 0.996 for Jev, 0.987 Qwen3.8-27B, 1.000 Clef, 0.965 Qwen3.5-9B. Confidence cascade: re-ask only when native confidence is below 0.7 gives 0.932 for Jev with a second request on 38% of states.
  - Real states (Sec. 6.2, 2,783 states, Table 3): Jev alone 0.806; asking probe questions +1.8, own answers +2.1, correct answers +4.0. Correct answers add 2.9-7.1 for most others; larger for SimpleJev-27B (+10.1) and Torchcast-27B (+8.6). Own answers repair 25-34% of facts-right/action-wrong states but break 2-4% of correct ones (Jev, Qwen3.8-27B, Gemma, Clef); OpenAI Decisions repairs 33% and breaks 6.8%.
  - Decision-oriented probes on 644 ALFWorld states (Table 4): Jev alone 0.716; decision facts +5.3, state digest +4.7, next sub-goal +16.3, facts plus sub-goal +21.3 (to 0.929). Jev's own answer to the sub-goal question is right in 66.8% of states; its own facts plus sub-goal add only 6.4. Incomplete summaries can hurt: Gemma 0.659 to 0.341 on states with one needed object seen and one unseen.
  - Controls (Sec. 7): removing history leaves BabyAI nearly unchanged (Jev 73.3 to 70.1) but collapses ALFWorld distance-ladder states (Jev 87.2 to 13.7). Matched edits: on ALFWorld observation edits, Jev changes its decision after a relevant edit in 71% of triples; on 83 policy-edit triples, systems that answer all edited probes correctly change the call after a relevant edit in only 22% (Clef) to 57% (Qwen3.8-27B) of cases, OpenAI Decisions 41%, Torchcast-27B 40%, Eikos-27B 72% with 0% after irrelevant edits.
  - Calibration of native distributions (Fig. 11, ECE %): Cygnet 2.6, Jev 6.8, Torchcast-27B 7.2, Perplexity Decider-27B 8.2 (coverage 89%), Decider-chat-31B 8.8, Qwen3.8-27B 8.9, OpenAI Decisions 11.8, Clef 11.9, Eikos-27B 11.9, Kev-9B 17.3, Gemma-4-31B 19.1, Vega-27B 26.6, CLM-8B 37.7, Laya 39.4. Gemma mean confidence 0.98 at accuracy 0.79; Clef and Kev-9B underconfident (mean confidence 0.66 and 0.47 at accuracies 0.76 and 0.62).
  - Cost and latency (Sec. 4, Table 1): Jev $8.79 for all 65,228 records ($0.13 per 1,000 states), OpenAI Decisions $18.69 ($0.29); Jev p50 205.7 ms, Laya 27.4 ms, Kev-9B 98.1 ms, Gemma 397.9 ms, Qwen3.8-27B 947.0 ms, GPT-6.1 about 2.3 s; GPT-6.1 about 73 times Jev's cost per state. A Jev rerun five days later matched on 96.3% of 2,783 states.
- Method/recipe and cost: for any deployed decision model, send the decision question and narrow factual probes about the same state as independent requests; cross U and D; check probe sufficiency; then test "ask facts, compose in code", add a sub-goal, or reroute low-confidence states. Cost: roughly doubling of cheap requests, plus a probe set per task.
- Limitations (authors): behavioral evidence only, no internal-computation claims; on natural states probes are not sufficient so U1D0 mixes decision failures with unasked facts; gold labels can be stricter than necessary (5-42% of simulator errors optimal) and 303 ALFWorld paired records carry wrong location labels (frozen labels kept); systems differ in serving stack, readout and input limits, so comparisons are of deployments not architectures; single decisions on frozen traces, not closed-loop execution; follow-ups cover subsets of systems; hosted models drift. My caveats: option order and option names/labels are frozen and not manipulated, so nothing here tests label or order effects; "missing evidence" is partially covered (misread fact, missing sub-goal) but never as an explicit "evidence absent" option; accuracy is partly limited by input-limit refusals (Laya, Quyet, Perplexity Decider), so low scores for those are not decision quality; headline "73-85% of errors follow correct reading" depends on probe quality and the non-sufficient probes on natural states; the sub-goal result is one domain (ALFWorld); the paper evaluates 17 systems at one point in time against a reasoning model with different readout.
- Relevance to the lab (populations/ensembles, cascades, calibration, missing evidence): Verdict: extends / lab-adjacent. Direct support for cascades and for ensembles of narrow questions composed by code: a confidence-gated second request on 38% of states reaches 0.932 for Jev, and own-answer composition reaches 0.96-1.00 when probes determine the action. Evidence that native confidence is usable for escalation for Jev (ECE 6.8%) but not for an overconfident readout (Gemma ECE 19.1%), which matters for any cascade built on K27, W12, A27, J, G. The error clustering across 14 systems (all fail on the same 141 states) is relevant to population/ensemble design: independent-looking errors across systems are not independent, so a population of different systems will not fix the shared hard states. Nothing on naming, order, or missing-evidence abstention; the lab's missing-evidence failure could be mapped onto the "fact not read" (U0) cell but the paper gives no abstain option.

## 2610.19536 — Typed Decision Models on Tabular Data
- Authors: Baowen Zhang (University of Wisconsin-Madison), Hangting Ye (School of AI, Jilin University; corresponding author), Hongyuan Zha (School of Data Science, Chinese University of Hong Kong, Shenzhen); v1 dated 14 Oct 2026; https://arxiv.org/abs/2610.19536; read: full text (main text and appendix Tables 3-15), accessed 2026-10-19. Independent academic group; no model built or ranked by the authors (they use released Jev, Clef, Kev-27B, and OpenAI's Decisions API).
- Systems and readouts: four decision models: Jev 1.13 (closed, via OpenRouter, revision 20260917), Clef (open, trained from Qwen3.8-27B; the authors run it with their own implementation of its release code), Kev-27B (open, trained from Qwen3.8-27B, official server), GPT-6 Luna Decisions (public-beta snapshot 6 Oct 2026). Three LLMs: GPT-6 Luna (temperature 1, reasoning off), Qwen3.8-27B and Llama-3.3-70B (greedy). Decision models return a probability per option; LLM confidence is read from ten temperature-1 draws, stated confidence, or first-token probability. Decision models get 16 rows per request (or 15 samples); LLMs get one row per prompt in row classification. Clef sorts the options in its release code, so option-order rewrites cannot reach it.
- Design: not pre-registered. Three tasks: row classification (ten TabLLM/FeatLLM datasets, 3,481 rows, Macro-F1), TabFact fact verification (2,000 claims, accuracy), ReTabAD anomaly detection (20 sources, 5,059 samples, AUROC). Each request is sent in original form and under 21 types of information-preserving rewrite (Table 12; option order reversed, options renamed A/B, renamed by synonyms false/true, no option descriptions, yes/no question, paraphrased instructions, hint appended, no task description; columns shuffled/reversed, list/sentences/JSON/Markdown formats, TabFact row shuffles, transposition, etc.; plus controls that remove or mislead information). A flip = decision differs from the original decision; invalid outputs count as flips. Re-send rate (identical request sent again) is the noise floor. Appendix C gives all results with intervals (cluster bootstrap for some tables). Trained baselines: best of eight classifiers (LightGBM) and five anomaly detectors, plus TabPFN-3.5.
- Key results (measured):
  - RQ1, original request (Table 3): row classification Macro-F1 Jev 52.1, Clef 58.4, Kev-27B 55.2, GPT-6 Luna Decisions 61.2, GPT-6 Luna 62.5, Qwen3.8-27B 52.2, Llama-3.3-70B 44.0, best trained 80.0; TabFact accuracy Jev 89.7, Clef 85.0, Kev-27B 88.8, GPT-6 Luna Decisions 78.7, GPT-6 Luna 79.0, Qwen3.8-27B 82.5, Llama 80.5; ReTabAD AUROC Jev 74.6, Clef 74.7, Kev-27B 81.2, GPT-6 Luna Decisions 80.5, GPT-6 Luna 77.3, Qwen3.8-27B 71.0, Llama 61.0, best trained 78.8. From about 64 labelled rows, TabPFN-3.5 and trained models match or beat every in-context model on row classification. LLMs generate 2.5-112 tokens per decision; decision models none. Latency (Table 4): Jev 0.08 s per row (row classification), 1.33 s TabFact, 0.09 s anomaly; GPT-6 Luna 1.62 / 1.59 / 0.73 s; price per million decisions Jev $10 / $38 / $16, GPT-6 Luna $81 / $62 / $68.
  - RQ2, option naming and order (Fig. 3, Table 13): for Jev, Clef and Kev-27B, renaming or reordering options changes 2-8% of classifications (at most 5.5 pp above re-send rates) and Macro-F1 by at most 1.3 points. Row classification flips: Jev reverse order 5.9, A/B 6.4, synonyms 7.6, no descriptions 5.4 (re-send 4.7); Clef 1.6 / 5.5 / 7.1 / 6.1 (re-send 1.6); Kev-27B 5.9 / 4.9 / 5.6 / 6.0 (re-send 0.6). The same rewrites change 14-30% of open-weight LLM classifications (Qwen3.8-27B reverse 13.6, A/B 25.5, synonyms 24.0; Llama reverse 26.8, A/B 30.4) and cost up to 11.5 points.
  - GPT-6 Luna Decisions is not robust to option order: it repeats its decision on identical re-sends (re-send flip 0.0 in Table 13), yet reversing options changes 22.7% of row classifications (text: 23%), 12.3% of TabFact verdicts and 21.7% of anomaly decisions; renaming changes 8-17% (row classification A/B 7.6, synonyms 8.7; TabFact A/B 9.6, synonyms 6.8; anomaly A/B 16.5). Among its classifications with probability at least 0.8, 14% flip, and 92-100% of all flips move to the option now listed first. The LLM GPT-6 Luna (temperature 1) has its own re-send flip of 13.3% (row classification).
  - TabFact option rewrites: Jev flips 2.1-2.4 (A/B, synonyms, reverse) vs re-send 1.9; Kev-27B 2.1-4.0; Clef 0.4-3.6 (reverse 0.4 because it sorts options). GPT-6 Luna (LLM) synonyms flip 47.6% with 43.7% invalid outputs and accuracy 47.0.
  - Question formulation extras (Table 13): "unverified hint appended" flips Jev 8.8 / 15.6 (Clef) / 4.7 (Kev-27B) / 17.6 (GPT-6 Luna Decisions) in row classification; Jev anomaly 15.6; "no task description" flips Jev 14.6 (row classification). Yes/no question flips Qwen3.8-27B 56.9 (Llama has 54.8% invalid outputs under strict parsing).
  - RQ3, table organization: format rewrites (list, sentences, JSON, Markdown vs array) change 12-21% of row classifications for every model (Table 15: Jev 12.8-15.0, Clef 11.8-14.3, Kev-27B 14.0-17.0, GPT-6 Luna Decisions 17.2-18.3), about ten times the re-send rate of the open-weight models. Column shuffle/reverse changes 15-23%. Items whose decision changes under at least one table rewrite (Table 5): row classification Jev 33.8%, Clef 31.7, Kev-27B 32.2, GPT-6 Luna Decisions 39.6, GPT-6 Luna 42.8, Qwen3.8-27B 31.8, Llama 35.5; TabFact 19.3 / 23.0 / 18.3 / 38.3 / 60.8 / 27.4 / 33.7; anomaly 21.1 / 25.8 / 17.7 / 29.9 / 63.4 / 23.3 / 53.4. Macro-F1 moves by under a point for some models and up to 7 for others. Removing information (values without names) flips 40.5% for Jev and drops Macro-F1 from 52.1 to 46.8.
  - Question shuffle within a request (Table 14, decision models only): Clef flips 14.9% of row classifications when its 16 questions are shuffled within a request; Jev 4.8 (re-send 4.7); Kev-27B 0.4; GPT-6 Luna Decisions 0.0.
  - RQ4, confidence as a fragility detector (Tables 6, 9): of each model's 25% most confident items, the share changed by some table rewrite is 0.9 / 4.6 / 0.6 for Jev (row classification / TabFact / anomaly), 1.4 / 4.1 / 0.7 Clef, 3.1 / 2.5 / 0.1 Kev-27B, but 1.8 / 15.5 / 4.2 for GPT-6 Luna Decisions, and 20.2-48.7 for GPT-6 Luna (ten draws), 22.5-61.6 (stated). Flip AUROC of low confidence: Jev 0.87 / 0.89 / 0.89 (row classification / anomaly / TabFact in table column order), Kev-27B 0.85 / 0.92 / 0.90, GPT-6 Luna Decisions 0.82 / 0.83 / 0.81, GPT-6 Luna 0.83 / 0.71 / 0.73, Llama 0.64 / 0.67 / 0.66. Error AUROC (predicting wrong answers) is much lower: Jev 0.59 / 0.65 / 0.82. Stable but wrong decisions make up 17-23% of decisions in row classification and anomaly detection (4-5% TabFact) and carry about as much confidence (0.67-0.86) as stable right ones (0.76-0.90).
  - Re-query recipe (Fig. 4): re-sending the 25% least confident rows in the four other formats and combining recovers 79-89% of the full re-query gain for decision models (64-86% for LLMs) at one extra request per row on average; full re-querying raises Macro-F1 2.0-6.4 points for six of seven models (Jev +3.5, Clef +2.0, GPT-6 Luna Decisions +4.3).
  - Margin model: flip rates predicted from the log-probability margin plus an item-independent shift match observed flip rates by decile (Fig. 5), which would explain why flips cancel in accuracy.
- Method/recipe and cost: run each item under information-preserving rewrites and compare against a re-send floor; use the returned probability to select items for re-query in alternate formats (one extra call per row on average for 79-89% of the gain); cost figures as above.
- Limitations (authors): each of seven models in one version; Jev and GPT-6 Luna Decisions are closed and may change, the Decisions API is in public beta; only the three tasks and subsets of each benchmark; 21 rewrite types leave out renaming columns and unit conversion; decision models read shorter contexts and suit fixed-answer tasks only. My caveats: the decision models receive 16 rows per request while LLMs get one row per prompt, so cost and sensitivity comparisons are not like-for-like; "option names/order barely matter" is shown for three models on binary or small-option tabular tasks with natural-language descriptions kept, not for a state that names an option key or for many-option choice; Clef sorts options so its order result is by design not robustness; the paper ranks no model of its own, but "best on two of three tasks" for Jev/Kev rests on one version each and single-run original-request scores; flip-rate is not accuracy and the authors acknowledge accuracy hides the flips.
- Relevance to the lab (option naming/rendering, option order, calibration, cascades): Verdict: extends the lab's option-name/order concerns on non-text states, and partly contradicts the Sun et al. (2609.26758) and Azizi et al. (2610.02586) label-override findings for fine-tuned decoder-style heads. Jev, Clef and Kev-27B (pointer/native heads on a 27B decoder) flip only 2-8% under A/B renaming, synonyms, or reversal, close to the re-send floor, which is consistent with the label-sensitivity benchmark's finding that fine-tuned decoder heads (Kev pointer head, letter-logit heads) are much less affected than encoders. GPT-6 Luna Decisions is the exception on order (23% on row classification, first-listed option absorbs 92-100% of flips) and is therefore a useful positive control for an order experiment. Calibration/cascade: returned probabilities flag fragile decisions (flip AUROC 0.81-0.93) but not wrong ones (error AUROC 0.59-0.84), and re-querying the least confident 25% recovers 79-89% of the gain, which is a ready-made cascade design: gate re-query by probability, vary a rendering (here table format; for the lab, option order or key naming). Lab idea: add a re-send noise floor and a within-request question shuffle test (Clef flips 14.9% when questions are shuffled) to every system's order test. Missing evidence/abstention: the "values without names" and "names attached to other fields' values" controls (flips 40.5% and 33.6% for Jev, Macro-F1 52.1 to 46.8 and 45.7) show the models do not abstain or collapse when information is removed or mismatched; this is not the lab's explicit missing-evidence option, but it is related.

## 2610.17205 — Releasing the Inner Jev: A Simple Recipe for Open Decision Models
- Authors: Jonathan Geuter*, Andrew Cheng*, David Alvarez-Melis (Harvard University; Kempner Institute); independent of the Jev vendor; arXiv v1 dated 12 Oct 2026; https://arxiv.org/abs/2610.17205; read: full text, accessed 2026-10-19. Gemma 4 31B / 12B, Qwen3.6-27B, Qwen3.5-4B, zero-shot and after training. Trained head: z = W0 h + A std(h) + b (Eq. 2), A and b initialised at zero, so the untrained model equals the zero-shot readout. Compared with hosted Jev 1.13.0 (API) and 13 public open systems run as their authors serve them (Eikos-27B, Quyet-1.0-Large/Medium, deck31b, AutoJev-27B, Torchcast-decision-12B, Winnow-12B, Cygnet, Clef, Plumb-4B, Open-Jev-27B, decider-4b-v2, SemIf). Order-invariant encodings (separate option segments) score 0.6 to 2.4 below the letter format (within noise, one run each). Option-order family on OpenDecisions (chance-corrected): trained 31B 87.2, zero-shot 31B 85.5, Jev 85.5. Every system gets the negation pairs right (Jev 100).

Cost 78 min on four H200 for 31B (about 5 GPU-hours), 64 min Qwen 27B, 40 min Gemma 12B, 23 min Qwen 4B. Inference is one forward pass; the adapter can be merged. Calibration by one temperature per question type fitted on 3,884 held-out questions, temperatures forced to at least 1 (a deviation chosen because Qwen temperatures below 1 hurt).

My caveats: the 4.3-point lead over Jev has a 95% interval of ± 2.5, so it is close to the noise; temperature scaling is chosen per competitor only if it helps that competitor (favours baselines, authors say) but Jev itself is reported without calibration (calibration hurts Jev, 80.1 to 78.8); the "same task composition as JevBench" claim rests on the published v1.6 split, not on the sealed items; benchmark has no missing-evidence or abstention family (the leaderboard abstention band is dropped for yes/no) and no embedded-instruction or option-naming family; relabeling and naming were not tested (letters are fixed); the claim "open models already possess System One capability" is measured on this dataset family and fails on knowledge-heavy MC (Jev ahead by 4.0). Authors' abstract claims match the body.
- Relevance to the lab: items option order, calibration, populations/ensembles (per-family spread), and evidence for the letter-logit class (the lab's W12/A27 style systems). Verdict: prior/extends for the letter-logit readout class (confirms that a plain letter-logit readout from an instruct LLM matches hosted Jev at about 30B with no training, and that the entire gain from training comes from adapting the LM and not the head); parallel for order sensitivity (6% answer change under reversal after training, with free text-sorted ordering as a fix); lab-only for missing evidence/abstention and option naming (not tested). Concrete ideas: (1) measure answer change under option reversal for each lab system and test a sort-by-text rendering as a free invariance control; (2) check the lab's calibration using type-wise temperature scaling fitted on a separate set and report ECE next to accuracy, since raw Gemma letter probabilities were strongly overconfident (Capability 72.9 raw vs 79.6 scaled); (3) treat zero-shot letter readout of the same backbone as a cheap baseline against which any lab fine-tuned head must be compared (head-only training gave nothing); (4) use the per-family breakdown rather than a single score when comparing systems or building ensembles.

  - Paired System-1 vs its base LLM (Fig. 5): non-agentic accuracy +2.9 (Vega-27B from Qwen3.8-27B), +5.6 (Microsoft-Decision-1 from Qwen3.5-9B), +11.0 (Kai-0.6B from Qwen3-0.6B-Base), -17.8 (CLM from Qwen3-8B), -2.6 (Decisions API vs GPT-6 Luna). Brier improves in four of five pairs (0.037-0.400 reduction; CLM worse by 0.034). Agentic step accuracy falls in all five pairs (1.2-19.3 pp).
- Method/recipe and cost: no new method. Open-LLM probability read-out (label token logits, one pass, prefix-tree scoring for more than 26 options with number labels "001"-"151"); closed-LLM verbalised JSON distribution; fixed per-family prompt. System-1 models called with their native interface. Local cost in H100-equivalent GPU-seconds, hosted in USD; units not converted.
- Limitations (authors): labels inherited from sources including their noise; tier-C instructions written by the authors; many sources are public and years old (possible training contamination); hosted models called through services so latency includes network and cost reflects prices on run days; sampled models got one draw so run-to-run variation is not measured. My caveats: no confidence intervals or seeds on Table 1, so rank differences of about 1 pp (Jev 72.6 vs GPT-6 Luna 71.2) are not tested; instructions are per-source and the same request is rendered differently per family (JSON options with descriptions for hosted Jev, "A/B/C" letter labels for open LLMs, JSON "option id" for closed LLMs), so rendering is confounded with model family, and the paper does not vary option names, order or label mapping; the key "Laya" row is the released general checkpoint with a 512-token input cut, which probably explains its low rank (the paper does not say why); the "no answer" columns suggest refusals/parse failures differ strongly across System-1 models yet are not examined; the headline "matches fast closed LLMs" is for non-agentic accuracy only and Jev is below both Luna models in loop success; Brier is a mix of hard and soft labels. Jev is the only closed Jev-family model measured; the authors state no connection to TypeSafe. The hosted Decisions API is in public beta and Microsoft-Decision-1 in alpha (Appendix B), so these numbers are point-in-time.
- Relevance to the lab: items calibration and cascades (Brier and ECE per model, plus latency and cost for routing between System-1 and LLM; the authors' explicit aim is "informing routing between System-1 models and generative LLMs") and, weakly, populations (30-model table is a cross-model population on identical requests). Nothing on missing evidence/abstention (the "no answer" share is a failure rate, not abstention), option naming, option order, or injection. Verdict: parallel for the calibration/ranking readout (the lab's per-system Brier and ECE would be directly comparable in form); background only for the lab's cascade question (their routing claim is not tested as a cascade, only as a cost-accuracy comparison); lab-only for naming, order, missing-evidence, injection. Concrete ideas: (1) report Brier alongside accuracy for each lab system and read the thinking result as a caution that a more accurate verifier may be worse calibrated; (2) reuse the "step accuracy does not predict loop success" point to justify scoring the lab's cascades end to end, not per question; (3) treat the "no answer" share (13-41% for several System-1 models on agent steps) as a coverage number to check on K27/W12/A27/J/G before comparing accuracies.

## 2610.21412 — JevAgentHarness: Benchmarking, Deploying and Training Decision Models That Share Control with LLMs
- Authors: Kunlun Zhu, Tao Feng, Xu Han, Heng Wang, Ling Yang, Xiangru Tang, Jiaxuan You, Heng Ji (UIUC; Princeton; Google for Tang); v1 dated 15 Oct 2026; arXiv 2610.21412; read: full text, accessed 2026-10-19 (appendix tables 26, 33, 35 and the recipe appendix read; other appendix tables skimmed). Independent academic, no stated link to TypeSafe. The benchmark authors did build ranked models: AgentDecision-4B and AgentDecision-0.8B appear in the paper's own model comparison (Fig. 4, Table 3), so the benchmark and a ranked entry share authors. Training labels for AgentDecision come from Jev's own outputs plus an answer key (distillation from the hosted model; the authors note that training on Jev outputs and redistributing derived weights depends on the provider's terms).
- Systems and readouts: hosted Jev (typesafe/jev-1.13, one-token read-out of option probabilities; confidence = probability of the argmax); open decision models Intern-Decision-4B, StartLux-Decision 0.8B/2B/4B/9B/27B, OpenJev / OpenJev-27B, JevK5, decider-4b, OpenAI Decisions API, and the authors' AgentDecision-4B/0.8B (Qwen3-4B + LoRA). Agent LLMs: Gemini 3.5 Flash (main), Flash-Lite, a few DeepSeek and OpenAI models. Generative deciders (verbalised) as references: Flash-Lite, Gemma 4 26B-A4B. Not in the set: Laya, Kev, Nimble, Von.
- Design: AgentDecisionBench with three levels. L1 isolated questions (1,114 BFCL v4 tool-choice items, 1,949 argument items, 928 When2Call items, converted to multiple choice). L2 step level: all models answer the same 5,314 "common states" of 200 new DecisionGym tasks, scored against an answer key of acceptable next steps. L3 task level: the decision model makes every tool choice of a running agent (every action in ALFWorld), no threshold, the LLM writes arguments. DecisionGym is the authors' simulated customer-service desk (68 tools plus finish, shuffled per task; 7 core tools, 1 ask-customer tool, 31 near-duplicate distractors, 29 unrelated tools; "must-ask" states where the right move is to ask the customer). Eight decision points (tool, arguments, action, memory write/read, reflect, stop, route) times five integration modes (Replace, Cascade, Assist, Guard, Trigger), 40 combinations. Pre-registered: models, tasks and tests, and the Stage-2 plan, registered before reading any Stage-1 result; eleven registered tests with Holm correction; non-inferiority margin 3 pp success (5 pp on tau2-bench). Many results (Table 1, Fig. 4, shifted/hard task sets, 4B/0.8B variants, public-data training) are explicitly "experiments added after Stage 1" and descriptive, not registered.
- Key results (author-measured):
  - RQ1 (Fig. 4, shifted DecisionGym tasks): isolated accuracy spread across models 5.1 pt, step-level spread 19.7 pt, task-level spread 57.5 pt. StartLux-9B was best on BFCL tool choice (92.2%) but solved 69.5% of tasks; AgentDecision-4B 89.3% BFCL, 91.5% of tasks; Jev 89.9 / 91.8 (step) / 82.0 (task); Intern-Decision-4B 88.2 / 75.9 / 34.0; OpenAI Decisions 90.6 / 86.1 / 66.0; StartLux-4B 91.3 / 86.5 / 49.0. Kendall correlation of step-level accuracy with task success 0.84. Claim: "isolated scores misrank decision models". The abstract's 69.5% is StartLux-9B, which has the highest isolated score in Fig. 4a (92.2%); OpenJev-27B also solves 69.5% of tasks.
  - Must-ask states: AgentDecision-4B 67.4% correct, Jev 58.3% (Table 3). All 34 of Jev's failed tasks began with an irreversible wrong tool choice, usually cancelling where the agent should have asked (App. G.7). Models trained on agent states made no such error. This is the closest result in the three papers to a missing-evidence failure (the right action is to ask for the missing information).
  - RQ2 (Fig. 5, Stage 1, Flash agent, Jev): Cascade at tool choice +0.0 pp success, 14% cost saved; at argument choice +0.0, 14%; Replace on tool choice -19.0 pp (67% cheaper); Replace on arguments -20.0; Assist (three-tool shortlist) -7.8 pp, 53.7% cheaper (92.0% solved vs 18.8% for a keyword shortlist); fitted thresholds were 1.00 for tools and 0.99 for arguments with Jev and Flash. The cascade with Jev handled 27.2% of tool and 20.8% of argument choices and cut cost 14.2% without changing the outcome of any of 500 tasks. With Flash-Lite as agent LLM the fitted threshold left every tool choice to the LLM (no savings). Fixed threshold 0.5: -21.5 pp (84.5% saved); fitted in shadow mode: +0.0, 14.2% saved (Table 2). Authors state a fitted threshold "protects success". On tau2-bench the cheapest passing delegation lost 8.1 points, so transfer was not shown. Chosen combination (tool + argument cascades + reflection trigger) with Jev: -2.2 pp success [-3.8, -0.8], failed the registered non-inferiority test; with AgentDecision-4B it passed (+0.6 [0.0, 1.4]) at 81.1% lower cost on 500 new tasks.
  - Threshold rule (Sec. 2.1): hand over when c(s) >= q_L - delta_C / V (q_L LLM accuracy on the choice, delta_C price of the saved call, V cost of a wrong choice); threshold fitted from 150 shadow-mode calibration tasks per agent LLM. Proof sketch assumes calibration (appendix). In the appendix, fitted thresholds beat the default tau = 0.8 in 70 of 72 cells.
  - Calibration of the decision model (appendix Table 26, L1): Jev tool-selection ECE 0.045, AUROC 0.87, 89.9% accuracy, 206 ms, $0.0167 per 1k; AgentDecision-4B V1 ECE 0.098, AUROC 0.71; Flash typed question ECE 0.075; Flash-Lite verbalised 0.080. When2Call: Jev ECE 0.080, 75.4%; AgentDecision-4B V1 54.0%, ECE 0.458 (training made it worse on this missing-information benchmark; authors show it improves after public-data training, Table 3 L1 85.1%).
  - Training (Table 3): Qwen3-4B untrained 13.5% shifted-task success; +SFT 96.0%; +public data 91.5%; StartLux-4B 49.0% to 98.0% with the authors' recipe; SFT gave almost all the gain (2.2 GPU-hours), GRPO added 4.5 GPU-hours and $26.53 of LLM calls without measurable gain. SFT target is 0.3 gold + 0.7 Jev probabilities where Jev ranks gold first, else the gold one-hot; loss is cross-entropy + 0.5 times a squared-error (Brier) term; 15,694 states from 587 tasks, 30.9% following a scripted mistake.
  - Deployment (Table 1, Table 2): hard DecisionGym 4.6-30.5% saved; ALFWorld 4B trained there 95.0% vs 90.7% reference, 89.0% cheaper, 18.2 s vs 37.0 s; unseen rooms 89.6 vs 88.8. Coding agents (routing to a strong or fast LLM): cost -7.0 to -10.5%, success varied (-6.0 to +7.9). 4B on its own GPU: 86.3% cheaper, 2.5 times faster; median 31 ms per answer vs 809 ms for a Flash call.
  - Failure modes: confident wrong choice at an irreversible step; new rule not seen in training (AgentDecision-4B solved 3.0% of hard tasks vs 88.0% for the LLM alone before refitting the threshold); guards that still call the LLM save little. With Flash-Lite as agent LLM the stop guard accepted 40.7% of the LLM's own wrong attempts to end the task.
  - Ensembles (App. G.8, Table 35): off-the-shelf majority and weighted votes did not match a trained model ("every off-the-shelf model fails 39% of the must-ask occurrences"; the models make the same mistakes). Must-ask accuracy: best single off-the-shelf 25.5%, off-the-shelf majority/weighted vote 47.3%, all-of-4-agree gate 61% with 97.5% on common states and 88.8% delegated; hosted Jev plus Decisions API weighted vote 31.5%, "both agree" 72%. Off-the-shelf plus trained models, weighted vote: 99.6 on common states and 100.0 on must-ask. Task-level success for the best single off-the-shelf model 78.5%. Authors read this as "voting does not replace training". In a registered follow-up, fitted thresholds made the OpenAI Decisions API (alone or gated with Jev) defer every tool choice, so neither ran at the task level.
- Method/recipe and cost: shadow-mode recording of the decision model on calibration tasks, per-decision-point threshold from the rule above, non-inferiority test on a paired task run, then freeze; adapters for mini-SWE-agent, pi, Codex CLI and Claude Code hooks. AgentDecision-4B training total reported as $192.93 for V1 including calibration (appendix).
- Limitations (authors): English; mostly Gemini agent LLMs; main tests are non-inferiority (equal success would need an equivalence test); thresholds and models are fitted to an agent's own runs so a new agent/tools/task family needs refitting, and best accuracy needs training on that agent's states; coding agents have small savings because free-text actions cannot be delegated; recorded prices/latencies change; no comparison with learned routers such as RouteLLM; GRPO added no measurable gain; adversarial observations and policy injection not tested, so results hold for benign states only; a guard should not be the only control on an irreversible action. My caveats: the benchmark and a ranked entry have the same authors and the benchmark was extended after Stage 1 in ways that favour the trained model (shifted tasks, hard tasks, "added after Stage 1" rows are descriptive, not registered); the trained 4B models are distilled from Jev, so "beats Jev" is a student exceeding its teacher on a task-specific distribution it was trained on; the abstract's 69.5% and 82.0% vs 91.5% compare models of very different cost and training data; Kendall 0.84 is over a small number of models; many headline cells are single runs of 100-500 tasks; the Jev result is for one fixed 68-tool synthetic domain with a template-derived answer key; DecisionGym results (LLM alone solved 99.4% of tasks) lean on harder variants added post hoc. The paper tests no ordering/naming perturbation of the tool list (tools are shuffled per task, with near-duplicates, and the authors mention renamed tools only in the "Shift" set: renamed tools and changed request wording).
- Relevance to the lab: cascades and calibration (primary: threshold fitted on shadow-mode trajectories, expected-cost rule, per-decision-point thresholds, non-inferiority margin), missing evidence/abstention (must-ask states, ask_user vs cancel_order; 34 of 34 Jev failures began with an irreversible wrong choice, usually acting where the right move was to ask), populations/ensembles (voting does not fix shared mistakes), and weakly option naming/order (tools shuffled and renamed in a shifted set; no analysis). Verdict: extends the lab's cascade question (their threshold rule and the observation that a fixed threshold lost 21.5 pp while a fitted one lost 0) and parallels the lab's missing-evidence failures (confident wrong action in a state that required asking); contradicts nothing in the lab but note that their threshold fitting assumes an in-distribution shadow run, which the lab's verification experiments may lack. Concrete ideas: (1) fit per-system confidence thresholds on a shadow run for the lab's K27/W12/A27/J/G and test cascade non-inferiority with the same 3-pp margin; (2) create "must-ask" (missing-evidence) cases and measure accuracy of each system separately, as they do (Jev 58.3% on must-ask vs about 91.8% overall step accuracy); (3) test whether an agreement gate (all-of-4 agree) improves must-ask accuracy in the lab's ensembles (they report 61% with the off-the-shelf gate vs 25.5% single, but only 88.8% delegated); (4) note confidence for hosted Jev is rounded to 1.00 (thresholds of 1.00 and 0.99), which suggests the probability is heavily saturated and the cascade is nearly a unanimity test.

## 2610.20778 — Verdict: Encode Once, Decide Many (Verdict-MQ)
- Authors: Avdhesh Singh Chouhan, Jack Perry (LEC AI, a company; the model and code are released Apache-2.0 at github.com/LEC-AI/verdict); v1 dated 14 Oct 2026; arXiv 2610.20778; read: full text, accessed 2026-10-19 (appendix ablation tables and the pitfalls list read; the rest skimmed). Vendor-affiliated model paper, not an independent benchmark. The authors built the ranked model (Verdict-MQ) and also ran the comparison (Laya, Jev, Verdict-CE) themselves on a third-party benchmark card (LocalLLaMA/typed-decisions, not authored by them). The paper discloses substantial use of an AI coding agent (Claude).
- Systems and readouts: Verdict-MQ (ModernBERT-base 150M / large 395M; encoder; one pass reads the state and all questions with a structured attention mask; the final hidden state at each option marker plus a question-type embedding goes through a two-layer MLP to a logit; softmax over the declared options). Baselines: Laya typed-decisions 421M (released specialist, fine-tuned on the benchmark's training split) and Laya general checkpoint (zero-shot), hosted Jev 1.13.0 via Vercel AI Gateway (one call per case, five questions batched; 387 of 400 cases succeeded), Verdict-CE (their own per-question cross-encoder), card-reported rows (meraGPT Decider 1, Featherless Simple Jev, MiniLM and ModernBERT per-workflow). Not tested: Kev, Nimble, Von, hosted decoder letter-logit models.
- Design: main benchmark LocalLLaMA typed-decisions: 4 synthetic workflows (agent-trace observability, customer service, invoice processing, security incidents), 1,200 training cases (6,000 decisions), 400 test cases (2,000 decisions), five typed questions per case; gold labels are the mean of three samples from a roughly 4B-class teacher; the card gives a "perfect scenario understanding" ceiling of 0.704, teacher self-agreement 0.735 and calls about 0.75 saturation. Also RACE, BoolQ, MultiRC (fine-tuned vs matched baseline; Laya general and Jev zero-shot references). Hyperparameters chosen on a 15% development split (hash of state); last epoch reported; 3-5 seeds; case-cluster bootstrap (10,000 resamples), McNemar and Welch's t; p-values unadjusted. Parts pre-registered: a "pre-registered rule" chose the 20% warmup, and the k=22 recipe came from a "pre-registered development-split search"; the authors state the whole process was adaptive and not test-blind in three named places and that a human saw live test accuracy on every typed-decisions run.
- Key results (author-measured unless marked card):
  - Table 1 (typed-decisions test, specialist mode, Acc / KL / Brier / ECE): Verdict-MQ large (395M, 5 fresh seeds) 0.801 ± 0.005 / 0.080 ± 0.001 / 0.045 ± 0.001 / 0.156 ± 0.007; Verdict-MQ base NLI-init (150M) 0.766 ± 0.008 / 0.103 / 0.057 / 0.135; Verdict-MQ base ModernBERT-init 0.681 ± 0.013 / 0.191 / 0.108 / 0.095; Laya typed-decisions (421M, measured) 0.767 / 0.117 / 0.061 / 0.214; Laya general, zero-shot 0.358 / 0.570 / 0.316 / 0.178; Jev general (measured) 0.734 / 0.829 / 0.148 / 0.028; Jev (card) 0.727 / 1.442 / 0.148 / 0.144; meraGPT Decider 1 (card) 0.768 / 0.096 / 0.052 / 0.180; Verdict-CE 150M 0.586 / 0.245 / 0.141 / 0.066; Uniform 0.308 / 0.444 / 0.238 / 0.169; Prior 0.470 / 0.347 / 0.189 / 0.088. Jev's measured accuracy 0.734 is close to the card's 0.727, but its KL (0.829) is far above the specialists' (0.080-0.117) and its ECE (0.028) is the lowest. The input-ignoring prior has a better ECE (0.088) than several systems, so the card recommends distance to soft gold over ECE.
  - Table 2 (paired by case, 5 seeds, vs Laya): accuracy +2.8 to +4.0 pp (p 0.0002 to 0.0018); KL -0.035 to -0.038; Brier -0.015 to -0.018 (all p <= 0.0002); temperature-matched KL difference -0.028 to -0.031 (all p <= 0.0002). Authors treat accuracy above about 0.75 as agreement with the teacher's quirks, not better decisions.
  - Initialization, not architecture, explains much of the lead: ModernBERT-init Verdict-MQ KL 0.191 (150M) and 0.153 (395M), both worse than Laya's 0.117; at a matched Laya-encoder initialisation but unmatched recipes, Laya's architecture 0.774/0.767 (mean 0.771) vs Verdict-MQ 0.767/0.758 (mean 0.763), a tie.
  - Autonomy dial (Table 3, threshold chosen on half the test cases and applied to the other half, raw confidence): at a 90% target, large Verdict-MQ auto-handles 62.2-71.1% of decisions at 89.4-92.2% realised accuracy; Laya 55.7% at 86.5%; AURC 0.0655-0.0725 vs 0.1069 (32-39% lower). At 95% target 41.2-51.2% vs Laya 36.8%; 98% target 24.3-29.0% vs 20.9%. The gain is ranking, not ECE-type calibration (raw ECE 0.156 is worse than the 150M model's). Coverage is per decision: whole-case automation (all five decisions clear tau) is only 19-27% of cases for Verdict-MQ and 2.5% for Laya; "strict dominance at 90%" fails for 2 of 5 seeds after temperature calibration.
  - Order and grouping invariance: by construction (shared position ids for all options, blocked attention between options); verified numerically: permuting options, answering a question alone, or batching with padding change probabilities by at most 5.4e-7 in fp32 (3.9e-3 in bf16, used for reported results, worst case over 20 random cases). On a trained checkpoint, permutation never changed the chosen option or crossed the autonomy threshold; answering alone never changed the chosen option but crossed the threshold in 0.75% of cases; bf16 vs fp32 flipped 0.3% of decisions. Invariance requires identical retained state tokens (a long state is truncated more when packed with more questions; none of the evaluated test cases was truncated at max_len = 2048, worst-case margin 567 tokens).
  - Position shortcuts (appendix pitfalls): with a fixed option order, a per-question model learned slot positions and dropped from 0.586 to 0.349 under permutation; random order at training time or invariance by construction removes this. Failure mode: if every option attends to every other option, the option markers collapse to one representation and the model outputs uniform distributions while invariance tests pass trivially. Ablation: shared option positions did not change accuracy beyond seed noise; ordered option positions 0.686 vs 0.681 full recipe (Table 7).
  - Latency (Table 4, one RTX 4090 Laptop GPU, bf16): packed 5-question case vs one pass per question: base 9.6 vs 12.5 ms (1.3 times) at batch 1, 5.8 vs 15.4 ms (2.7 times) at batch 8; large 13.4 vs 24.5 ms (1.8 times) and 11.4 vs 32.0 ms (2.8 times).
  - Standard benchmarks (Table 5, accuracy %): RACE Verdict-MQ 77.4 ± 0.4 vs baseline 78.9 ± 0.1 (Laya zero-shot 45.5, Jev 93.3); BoolQ 76.2 ± 3.1 vs 81.0 ± 0.6 (Laya 76.0, Jev 91.3), five test seeds from 72.3 to 79.4, with roughly half of runs stalling near the majority-class rate (62%); MultiRC 80.6 ± 0.5 vs 71.6 ± 4.9 (Laya 54.9, Jev 90.0). Zero-shot hosted Jev beats every fine-tuned encoder. Cost of sharing the state: letting each question read its own copy of the state (k=22) gains 0.9-3.5 points on RACE and MultiRC at 1.4-2.5 times the latency, and nothing measurable on typed decisions.
- Method/recipe and cost: attention-mask packing with four rules (state attends only to state; each question block attends to the state and itself and starts at the position right after the state; question tokens attend to all its options while each option attends only to the state, question and itself; all options of a question share position ids and the sliding window is on position ids), cross-entropy against soft labels plus squared earth-mover term for ordinal score questions, choice questions with more than two options trained on random option subsets (probability 0.3, gold kept), existing special token ([CLS]) as option marker (0.790 to 0.801 vs a new token), 20% warmup. Training on one RTX 4090 Laptop GPU. An optional option mixer (set attention over the markers) is neutral (0.764 ± 0.005 vs 0.766 ± 0.008 on test).
- Limitations (authors): typed-decisions is small, synthetic, labelled by a small teacher and not peer-reviewed so high scores partly measure agreement with the teacher; headline Verdict-MQ results are specialist results and the generalists they trained fall below the input-ignoring prior; RACE remains 1.5 pp below the matched baseline even at k=22; BoolQ unstable; comparison with an open system is like-for-like only on typed decisions against Laya's released specialist; Jev called by an unpinned alias so numbers may not be reproducible; email labels from LLM teachers; single laptop GPU timings; adaptive research process; p-values not adjusted for seeds/configurations; the re-fine-tuning of Laya used hard labels and no temperature scaling, which favours Verdict-MQ on distribution metrics in that comparison. My caveats: the paper's accuracy lead over Laya is partly NLI-initialisation (authors' own reading), so "architecture wins" cannot be inferred; the benchmark labels come from a roughly 4B teacher so a "better KL" means closer to that teacher; the pre-registered parts concern recipe selection (warmup, split depth), not the invariance claim; the invariance is shown on option permutation and question grouping only, not on option renaming or label content (the model renders option text and descriptions only, via a marker token read-out, so the label-override effect found elsewhere would depend on the description text, which was not tested here); the paper's Jev row used a batch call with all five questions in one request, a different rendering from one call per question.
- Relevance to the lab: option order (primary: order invariance by construction, with the failure case of fixed order learning slot positions, 0.586 to 0.349), calibration (raw-confidence autonomy dial and temperature-matched comparison), cascades (coverage at 90/95/98% accuracy targets; per-decision vs whole-case coverage gap), populations (the 5-seed ensemble is of seeds, not a deliberate population). Verdict: extends the lab's order experiments (a mechanism that removes order sensitivity, which the lab can use as a reference: any lab-measured order effect on pointer-head or letter-logit systems should be absent in this class, and present in the others); parallel for calibration (threshold-based auto-handling, as in 2610.21412); lab-only for missing evidence, naming and injection. Concrete ideas: (1) permute option order for K27/W12/A27/J/G and compare accuracy change to Verdict-MQ's near-zero (their 0.75% threshold-crossing rate when answering alone gives an effect-size scale); (2) report coverage-at-accuracy-target tables (90/95/98%) with the threshold chosen on one half and applied to the other half, per decision and per whole case; (3) the "position shortcut" pitfall (0.586 to 0.349 under permutation) is a ready-made control: a lab system trained or prompted with fixed option order may lean on slot position, so test a shuffled-order condition for the lab's choice questions; (4) Verdict-MQ is released (Apache-2.0) and can be added as an extra order-invariant encoder control, but it is a specialist trained on four synthetic workflows and its generalist variants fall below the prior, so it is not a plug-in for the lab's domain.
